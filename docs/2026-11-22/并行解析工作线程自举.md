# 并行解析工作线程自举

## Intent

将并行解析工作线程领取批次、命中或解析的分派和失败停止迁入 Source。原生层继续负责启动与汇合线程、原子操作和解析区分配。

## Data

起点为 `94729f6e7`。正式入口为 `ParseCache.prefetchInto`。旧工作线程在 Zig 中推进批次，在固定缓冲区调用 ZX 分类，随后登记命中或创建解析结果。上一阶段已迁移汇合后的顺序提交。

```mermaid
flowchart LR
    Worker[原生线程入口] --> Next[ZX 核对失败状态并请求批次]
    Next --> Classify[ZX 识别已缓存与需解析的行]
    Classify --> Ready[登记命中或暂存新的解析结果]
    Ready --> Next
    Ready -->|解析失败| Stop[标记失败并停止领取]
```

```mermaid
flowchart LR
    Source[借用路径与源文本] --> Compare[比较已有文本与摘要]
    Compare -->|命中| View[交付原有解析视图]
    Compare -->|变化| Digest[直接写入工作线程摘要槽]
    Digest --> Parse[创建新解析区]
    Parse --> Commit[汇合后顺序提交]
```

## Edges

保留原工作线程数、批次上限、原子顺序与结果所有权。工作线程只写已领取的行。失败前已经领取的批次按原规则完成，汇合后继续由 RX 处理已就绪结果。

## Answer

覆盖同文本、摘要命中、解析变化和工作线程失败。集中核对引导、批量解析回归、常驻编辑及固定性能对照。

### 正式路径

- Zig 完成线程启动和汇合，并绑定现有路径列、文本列、缓存索引和每线程缓冲区。ZX 计算领取宽度和尾批边界，使用原有原子操作领取、查询及标记失败。
- 同一批先核对缓存，再依次交付命中视图或暂存解析。摘要直接写入该工作线程的既有摘要列，后续比较和解析借用这份结果。SHA-256 后端保持一致，移除了旧的中间哈希缓冲和复制。
- 已领取的批次只在自身解析失败后提前停止。其他线程报告失败时，在下一次领取前停止。已成功暂存的解析由上一阶段的 RX 顺序提交。
- 初始引导保留原生工作线程。正式 Zig 接口绑定缓冲和原子值，并执行解析区分配和结果写入。

### 正确性核验

空临时分配区通过三项核验，涵盖文本命中、摘要命中、直接哈希、解析失败停止和完成已领取批次后观察同伴失败。

真实缓存接口通过三项核验，覆盖跨工作线程批次的 193 项解析与部分内容变更、命中视图顺序、各项摘要以及分配失败时的成功前缀。模块生成、语义缓存、RX 推导和解析缓存共 182 项回归通过。

十次常驻请求的分析、复用和发射计数与上阶段一致，增量与同输入冷生成的产物逐字节相同。使用同一四模块项目交错计时，每种工具各完成 192 次正文编辑和 192 次纯 RX 编辑。正文请求中位数从 0.84 ms 到 0.81 ms，纯 RX 请求从 0.67 ms 到 0.65 ms。
