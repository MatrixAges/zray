# 循环表示切换与结果恢复自举

## Intent · 最终目标

将初值绑定与表示转换、投影字段重建、循环写回和返回路径的选择迁入 Source。保留普通、投影和深层循环原有的存储及失败语义。

## Data · 可用证据

初值和循环结果的策略已由 ZX 选择，但 Zig 宿主仍根据计划决定进入哪个作用域、如何写入初始值、何时重建字段，以及选取哪个返回分支。字段重建还需要在原值发布后依次执行替换、布局解析和结果构造。

## Edges · 边界与限制

先计算初值，再进入循环状态作用域。字段投影按原顺序交付，写入完成后才恢复或构造结果。循环的临时作用域在错误退出时仍由同一个所有者解绕。保持引导 seed 的执行路径和静态链接。

```mermaid
flowchart LR
    A[初值和所有权计划] --> B[Source 准备表示]
    B --> C[循环参数和条件]
    C --> D[字段更新与循环写回]
    D --> E[结果恢复和发布]
```

```mermaid
flowchart LR
    P[字段投影计划] --> X[发布访问表达式]
    X --> R[解析需要替换的字段]
    R --> L[选取布局]
    L --> O[重建输出]
```

## Answer · 交付与验证

### 已迁移职责

RX 根据初值绑定结果打开或关闭相应的表示转换，ZX 选择存储转换和赋值类型。投影字段发布原访问表达式后，Source 选择替换、布局和构造步骤。循环结果先发布守卫，再转换或接上延迟消费，最后由 Source 选择跳过循环、投影结果或普通守卫的返回路径。[主流程](../../packages/genz/src/analysis/iteration/workflow/execute/run.rx) · [字段重建](../../packages/genz/src/analysis/iteration/fields/ownership/execute.rx) · [结果发布](../../packages/genz/src/analysis/iteration/result/finish/execute/run.rx)

正式路径退出 Zig 的初值和赋值分派、字段重建顺序及结果包装选择。Zig 仍持有节点缓冲、参数表和作用域，负责声明布局、后续更新作用域和失败恢复。清理继续使用原帧的作用域恢复顺序。下一批一起处理参数进入和写回、作用域恢复与增长记录的交接。[帧恢复](../../packages/genz/src/zx/iteration/execution/frame.zig) · [参数作用域](../../packages/genz/src/zx/iteration/parameters.zig) · [增长记录](../../packages/genz/src/zx/iteration/renewal.zig)

### 一致性与性能

候选以 Zig 0.17.0、ReleaseSmall、16 个引导分区构建，通过 25 个步骤。SHA-256 为 `59f5a364dc334fb45f8c4fe92c40cf6fdd8515da61acf88fd933a5aa4def882d`。主、增长、集合与执行四组清单共 16,255 份文件逐字节一致，排除工具身份戳。三个小清单入口的生成代码中没有新建堆对象、复制数据和预留容量的调用。

两版均以 Source 引导器构建并执行 Source 分析和生成。复用 735 入口固定清单，关闭常驻，交替三轮取中位数。冷暖生成均使用同一配置，11,753 份计时产物以及所有权缓存载荷一致。

### 回归

循环列、模块化循环、字段事实、循环初值所有权、原生借用、对象转移与迭代调用七组通过 404 个构建步骤、568 项 Zig 测试和 25 项 Node 集成检查。对象转移检查的累计分配量在初值、首轮和 64 轮均为 1,966,434 字节。19 个 RX/ZX 文件通过 lint 和格式检查。原始日志位于 `.zig-cache/verification-tmp/loop-representation/`。
