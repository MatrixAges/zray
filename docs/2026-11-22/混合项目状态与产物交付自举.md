# 混合项目状态与产物交付自举

## Intent

将混合项目共享表的安装顺序以及入口正文、调用观测和公开导出的交付迁入 Source。保持原有借用、诊断和分配失败顺序。

## Data

起点为 `2746f0f0f`。`State.init` 在 Zig 依次安装类型、原生模块、正文槽位、名义来源、函数和 Store 初值。入口计划和导出前缀由 ZX 决定，原生路径负责按计划发布，并遍历入口调用元数据。

```mermaid
flowchart LR
    Signatures[签名与初始表] --> Columns[安装类型、原生模块和结果槽]
    Columns --> Origins[登记名义来源]
    Origins --> Publish[安装签名函数和 Store 初值]
    Publish --> Bodies[执行混合正文]
```

```mermaid
flowchart LR
    Bodies[已完成正文] --> Entry[选择可执行或纯类型入口]
    Entry --> Observations[恢复调用与返回值视图]
    Observations --> Exports[依声明顺序发布导出]
    Exports --> History[保留增量历史]
```

## Edges

类型、函数和 Store 初值使用同一结果区语义。入口观测的私有 Task 函数和借用前缀保持各自的生命周期。导出只复制需要拥有的名称和路径，保留错误前已经完成的工作及原错误优先级。

## Answer

验证共享表、编译库公开导出、入口调用观测、失败清理、缓存与引导产物。集中完成固定冷暖对照。

### 正式路径

- RX 按原顺序安装类型与原生表、结果槽、名义来源、签名函数和 Store 初值。每一步继续使用现有表存储与校验入口。
- ZX 直接决定纯类型入口、可执行入口、可见函数前缀及错误消息，并把选定的入口写入原结果槽。输出继续借用已联结的函数、声明和 Store 初值。
- 调用观测的脱离与恢复由 ZX 遍历。共享前缀在分析后用最终表重新绑定，私有 Task 的函数表沿用其独立存储。原生层提供必要的后缀拼接和视图写入。
- 导出按原顺序校验并写入目标行。名称错误优先于同一项未编译的根，前面各项的分配失败仍先返回。只有名称和路径转为结果所拥有的存储。
- 原生层继续持有数据结构、分配器和物理记录操作。初始 seed 使用同一组单项操作，导出列的直接借用使用 64 位索引布局。

### 正确性核验

当前源码的五份引导清单共 17,431 个文件逐字节一致。十次常驻请求的分析、复用、发射计数与上阶段一致，每次成功请求的生成产物与同输入冷生成一致。

初始 seed 的 `bootstrap-parser` 通过 32 个构建步骤。

模块生成、语义缓存、RX 推导、库链接和 Store 初值共 240 项回归通过。初值组的四个旧用例最初在候选和 `2746f0f0f` 上同样失败。正向夹具现通过 RX 调用编译库，继续核对相同和不同实例、初值再发布与分配失败清理。ZX 用例检查模块边界的诊断。只补跑了受夹具修改影响的用例。
