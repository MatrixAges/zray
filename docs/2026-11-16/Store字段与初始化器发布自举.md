# Store 字段与初始化器发布自举

## Intent

贯通 Store 定义的字段布局、初始化表达式和对象 IR 发布。复用模式校验已经计算的布局，保持求值顺序、类型编号及错误位置，避免重复申请字段名列。

## Data

从 `297a87d7` 沿 `project.derive → registry.loadSignaturesIn → Store.analyzeWithValues` 追踪 Store 校验与初始化器。相关的 Store 模式、项目分析、RX 程序构造与对象类型构造涉及约三千行 Zig。字段区间计划和字段排序位置已有 ZX 实现，正式路径仍由 Zig 重新构建字段偏移并发布对象载荷。

## Edges

字段类型按声明位置解析，初始化表达式按对象片段和字段的原顺序求值。类型构造经 Source 借用字段名和 ID 列，seed 可能排序该列。宿主负责解释原 AST、分配和持久化列，任何源列的借用都必须覆盖生成调用。

## 实现与边界

- Store 模式校验把已经为重复字段检查构建的偏移列交给布局阶段，多个对象片段共用同一份数据。只有一个片段时直接使用原 AST 的字段数。
- Source 区间规划先找属于当前对象的连续字段，再统计剩余的不连续部分。只有连续区间时直接从端点取总数。正式 Source 路径复用类型构造的字段名列，保持声明顺序。初始 seed 的类型构造仍会原地排序，因此保留其原有顺序缓冲。
- 对象发布由 RX 编排。ZX 对齐规范字段的索引，使用标准库把已经求值的 ID 写入目标列，并复用表达式链接中的范围头发布。宿主提交所有列长度。字段解析、类型解析调用、表达式生命周期和内存分配仍由 Zig 驱动。

## 验收

- 用相同输入生成四个既有 Store 场景，并将同一计数器的两个字段拆分到中间隔着独立对象的片段，额外核对深层嵌套场景。五份生成 Zig 与上阶段安装版逐字节一致。新安装版构建的跨片段 Store 应用正确初始化原计数器，并能执行读写调用。
- 新入口通过上一阶段 Source 工具生成，自举工具与安装版构建通过。修改的 RX/ZX 通过 lint，Zig 通过格式检查。
- 默认 seed 构建通过。RX 文本、类型推导、Store 执行、库初始化器、Store 重发布和 RX 库边界共通过 325 项回归，安装版 Store 路径和应用状态共通过 24 项检查。
