# 库后端公开入口发布自举

## Intent

让库后端从公开导出一次确定分析根和 facade 成员。在复用共享函数分析的同时保留独立入口、通用函数版本和生成顺序。

## Data

从 `f5cfed07` 的 `emitLibraryVerified → backends/zig/library.create → function_sources.createJobs` 追踪。涉及库分析与链接、后端批次、共享函数可达性和生成缓存。原后端先遍历成员登记分析根，随后按模块重复遍历成员制作 facade，再扫描成员确定需要通用版本的函数。

## Edges

保持默认入口与具名成员的顺序、intrinsic 的静态语义、重复成员 ID、Store 初始化器和现有缓存键。扫描借用已链接的导出，输出描述符只在生成期间使用。Zig 保留分配、结构体和生成器调用的宿主适配。

## 实现与边界

- 收集器直接借用默认入口 ID 及嵌套成员列。库链接和工件校验保证 intrinsic 没有运行时函数 ID，具名运行时成员具有合法 ID。收集保留默认入口和具名函数原有的顺序及重复项。
- 一次遍历将分析根、具名函数 ID、成员名称和各导出的累计端点写进预留空间，同时标记需要发射通用版本的函数。库后端用同一批结果供共享分析、可达性分析、facade 导入和生成单元选择。生成的遍历未引入分配或拷贝调用。
- 公开 facade 及其生成内容仍由返回的库 Bundle 持有。根、公开成员计划、临时批次和生成任务的空间在生成返回时释放。成员名称直接借用库导出的文本。
- Zig 仍管理后端分配、生成单元和 facade 的 ABI 组装、缓存生命周期与线程调度。嵌套列读取使用宿主借出的 opaque 句柄，使用期只覆盖当前同步调用。

## 借用边界

应用源码使用普通对象、列表和字符串，编译器负责确定借用范围、转移和释放。此前 `std:memory` 公开了自举使用的宿主缓冲区接口。声明和实现已迁入编译器，原生借用适配只在引导清单内注册。编译器内部使用该接口的源码已切换到私有注册项。等这些表格的数据模型由生成代码直接拥有，继续改用普通 ZX 集合与借用分析。应用跨调用共享状态由 Store 管理。

## 验收

- 初始 seed 和上一阶段的 Source 工具各自生成并构建了 760 入口的新引导器。由新的 Source 引导器构建 16 分区安装版成功。改动的 Source 与 Zig 格式检查通过。
- 编译器现有的导入解析 barrel 公开 `advance` 与 `resume`。该库的 15 份发布文件、Store 库的 14 份发布文件，以及三组 Gateway 的 42 份生成模块各自与上一版逐字节一致。
- 新安装版拒绝普通项目导入原来的 `std:memory` 和私有原生接口。306 个既有 ZX/RX 文件的改动仅涉及内部导入及其排版。
- 库链接、库执行和借用生命周期回归共通过 54 项 Zig 测试与 28 项 Node 检查。普通 ZX 数组的元数据视图与直接操作都分配一次、共 80 字节，借用视图读取也保持同样的分配次数和大小。
