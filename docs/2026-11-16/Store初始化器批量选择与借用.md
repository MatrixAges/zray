# Store 初始化器批量选择与借用

## Intent

让 Source 一次选择一批需要的 Store 初始化器。应用生成和库链接都借用定义中已有的程序描述符，保持声明顺序、错误优先级和公开输入形式。

## Data

从 `e0558db7` 沿 CLI 应用生成与库发布入口进入 `store.collectInitializers`，再追踪库链接、后端校验和发射。相关的 Store 定义、项目接口、库链接和后端初始化器路径涉及约三千行 Zig。选择规则已由 ZX 执行，每次最多返回一行。每个结果还把完整 `Program` 描述符存入一个临时列表。

## Edges

借用只在当前应用发射或库链接调用内存活，定义数组和程序正文保持只读。库输出保留原有的独立所有权。未使用的初始化器仍跳过，遇到无效公开成员时保留已经选择的前缀和原错误顺序。

## 实现与边界

- RX 在无 Store 需求时直接返回。ZX 每次向固定栈缓冲写入最多 32 个按声明排序的行号，同时返回续扫位置与成员校验结果。先发布批内已经选定的前缀，再处理无效成员。宿主仍负责导出成员的 ID 投影、定义迭代及分配。
- 选择结果存储标识、版本和指向定义中原程序的只读引用，Zig 校验器和库链接直接借用该引用。应用发射需要改写产物文件名时才构造本地描述符。应用的选择列表由临时 arena 管理。
- Zig 库与生成后端仍接收原有按值输入。正式 CLI 使用借用入口，链接或发射生成的持久产物继续由其结果 arena 拥有。

## 验收

- 原 Store 发布样例的 14 份产物逐字节一致。将同一已有样例扩展到一个入口读 41 个对象后，54 份库产物仍逐字节一致。新安装版构建的 41 对象应用运行得到 `123`。
- 新 Source 入口通过原引导器生成，Source 引导器和安装版构建通过。改动的 RX/ZX 通过 lint，Zig 通过格式检查。
- 种子路径构建成功。库链接、初始化器、Store 重发布、编译库调用、库边界和 Store 运行通过 111 项 Zig 回归，另通过安装版的 8 项应用状态检查。现有按值接口由原有库链接和后端用例执行。
