# 模块联结图依赖边自举

## Intent

沿模块产物、依赖图和库联结推进自举。让 Source 直接从模块依赖记录构建图，去掉 Zig 的依赖筛选循环和临时路径数组。

## Data

`e083bffa` 已将依赖目标保存在可借用的固定字段中。联结仍先由宿主收集源码边与偏移，再由 Source 把路径映射成模块 ID，最后用共享依赖图遍历检查入口。

## Edges

保持模块及边的输入顺序，沿用入口可达范围、缺失边和循环的诊断。路径内容直接借用，偏移写入最终缓冲，模块 ID 构造后供联结复用。保留初始 seed 路径。

## Answer

```mermaid
flowchart LR
    Artifacts[模块产物] --> Registry[Source 路径索引]
    Artifacts --> Edges[Source 依赖边收集]
    Registry --> Edges
    Edges --> Walk[共享依赖图遍历]
    Walk --> Link[签名与函数联结]
```

```mermaid
flowchart LR
    Modules[模块列表] --> Columns[借用依赖类别和路径]
    Columns --> Lookup[源码边映射模块 ID]
    Lookup --> Numeric[数字边与模块行偏移]
    Numeric --> Order[入口联结顺序]
```

用实际模块产物验证缺失边、循环、联结顺序和归档执行。沿用固定 Source 基线和相邻阶段的同输入产物与性能对照。

## 实现与边界

`compiler.project.artifact.linker.link` 的 Source 路径调用 `graph.prepare`，由 `order.rx` 依次执行路径登记、入口查找、依赖边构建和共享图遍历。Zig 提供借用的依赖列以及最终顺序和偏移的可写缓冲。路径查找失败保留缺失边标记，遍历从入口发现该边时保持原诊断。

`edges.zx` 只向数字边数组追加模块 ID，省去已筛选路径的中间切片列表。生成的 Zig 在容量足够时原地追加，仅在扩容时搬移已有 ID。依赖类别和路径借用模块产物的现有存储，联结完成时释放图的临时 arena。

产物联结 API 由 `test-link-runtime` 从独立提取的模块调用。CLI 的混合项目编译和库发布还有各自的 `source_link`、`program_link` 路径。模块路径描述符目前仍由宿主收集，模块类型合并、逐模块签名与函数联结的状态也继续由宿主持有。

## 验收

- 2 个定向生成入口通过，候选 Source 引导器构建的 22 个步骤通过。改动的 RX 和 ZX 源码通过格式与 lint 检查。
- `test-link-boundaries`、`test-link-runtime` 和 `test-library-link` 共 68 项通过，覆盖缺失边、循环、接口不匹配、分配失败后的清理和从独立模块产物重联结。
- 相邻工具对同一份 736 入口清单生成的 11,784 个文件一致。5,361 条生成缓存记录逐一核对键和负载摘要。无改动重跑保持输入快照及生成时间戳，所有权缓存摘要为 `e6080741444c8eb2bbc8762205ffdb55f1086765083f7c568a70e80a1e3db51a`。
