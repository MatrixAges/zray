# 生成缓存文本发布自举

## Intent

让应用和库的批量生成在 RX/ZX 中决定缓存命中与重新生成的文本布局和发布。返回的 Bundle 独立拥有文本，缓存可以在后续覆盖原记录。

## Data

从 `251e7a92` 的 `Batch.identify → function_sources.createJobs → cache.fetch / record / put` 追到分区发射和持久缓存写入。Source 已提供命中分类与前缀偏移。Zig 仍逐项将命中拷入结果，逐项分配新生成文本，再按任务位置组装。范围内的 Zig 涉及生成批次、缓存入口、发射与工作线程。

## Edges

先完成缓存命中文本的发布，再更新可能替换存储的缓存记录。工作线程只借用已完成的发射结果。缓存命中和重新生成各使用连续结果存储，线程写入的范围由前缀布局保证互斥。保留原有缓存键、磁盘格式、写回顺序、签名和文件顺序。Zig 负责原生分配器、工作线程和磁盘 I/O。

## Answer

```mermaid
flowchart LR
    Fetch["识别任务并读取缓存"] --> Plan["ZX 分类命中和待发射"]
    Plan --> Hits["ZX 发布命中文本"]
    Hits --> Record["登记缓存读取结果"]
    Record --> Emit["发射未命中的任务"]
    Emit --> Layout["ZX 计算新文本位置"]
    Layout --> Publish["ZX 发布新文本"]
    Publish --> Remember["按原顺序写入缓存"]
```

```mermaid
flowchart LR
    Rows["借用文本列"] --> Offsets["前缀偏移"]
    Offsets --> Bytes["写入 Bundle 持有的互斥区间"]
    Bytes --> Slots["将切片发布到原任务位置"]
    Slots --> Bundle["应用、库与分区"]
```

## 实现与边界

- 缓存命中继续使用 Source 分类得到的偏移。新生成文本由 ZX 计算前缀偏移，整批使用一个由 Bundle 持有的连续缓冲区。
- 两条路径都借用文本列，按稳定的任务位置发布。ZX 在一次调用内处理最多 16 个位置，每段的写入区间由偏移确定。发布的是目标缓冲区的切片，回收缓存条目或发射暂存空间后仍可读取。
- 先发布所有命中，再登记缓存读取结果。新文本发布后按原有任务顺序记入缓存，读取、重试和增量命中逻辑沿用旧契约。初始 seed 继续使用已有的逐项布局和复制实现。
- Zig 保有生成批次、缓存索引、工作线程、磁盘 I/O 和实际分配器。它将借用列和目标缓冲区交给 ZX，并在更新缓存前等待工作线程退出。缓存键仍使用原有实现。

## 功能验收

- 实际生成的分类、偏移及发布入口在空容量分配器中通过。覆盖命中与未命中混排、跨段发布、空文本、非 UTF-8 字节、缺失行以及来源与目标指针的独立所有权。
- 上一代 Source 引导器和初始 seed 分别生成并构建 765 入口的新版工具。新版 Source 工具生成的 16 分区安装版通过构建。
- 相邻两版安装工具的具名导出库 15 份文件和 Store 库 14 份文件分别逐字节一致。
- 23 项模块生成回归和 4 项安装版增量运行检查通过，覆盖销毁缓存后的输出所有权、缓存记录替换与分配失败重试、磁盘损坏记录、修改输入和原生 ABI。
