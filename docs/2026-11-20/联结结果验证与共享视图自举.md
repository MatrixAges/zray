# 联结结果验证与共享视图自举

## Intent

让正式工件联结在 RX 结果发布链内验证已登记的函数、类型、原生模块和公开导出。复用普通语义缓存的借用方式和 IR 验证规则，保留两条路径各自的错误与生命周期约定。

## Data

工件联结在 RX 内完成递归入口登记、公开绑定与 Store 重映射，随后 Zig 先组装 `ir.Program`，再调用单独的验证入口。缓存恢复已能在 RX 内直接借用发布后的列。

```mermaid
flowchart LR
    Bound["已绑定依赖和类型"] --> Publish["RX 登记递归入口并发布导出"]
    Restored["普通缓存恢复"] --> Borrow["借用可见函数、类型与导出"]
    Publish --> Borrow
    Borrow --> Verify["共用 IR 验证"]
    Verify --> Accept["交付结果与已验证前缀"]
    Verify --> Reject["拒绝结果或恢复旧前缀"]
```

## Edges

验证前刷新函数切片和导出视图。联结发布保留验证临时区，返回的 IR 描述符和数据继续由持久区持有。物化失败、IR 验证失败和分配失败保留各自错误。初始 seed 沿用原路径，已组装的 IR 消费者继续调用现有通用验证。

```mermaid
flowchart LR
    Columns["可见函数和类型列"] --> Views["借用视图"]
    Exports["持久区导出及常量行"] --> Views
    Views --> Scratch["验证临时区"]
    Scratch --> Status["成功状态与前缀"]
```

## Answer

正式工件联结在 RX 中登记递归入口、发布导出、选择最终正文，再通过共用入口验证可见列。普通缓存恢复使用同一验证入口继续校验新前缀。Zig 只在两条路径验证成功后组装最终 IR，并管理列借用和分配器。直接追加已组装程序的入口仍在 Source 中执行自己的准入验证。

### 引导与回归

以 `1babb5442` 的 Source 引导器构建候选及初始 seed，共 27 步通过。候选重新生成当前 922 个入口的正式清单，14,253 份文件逐字节一致，工具身份戳除外。工件联结边界、原生与库联结、工件提取及槽位、Store 执行和普通语义缓存共 228 项 Zig 测试通过。安装版通过原生 ABI 与 5 项磁盘缓存集成检查，共 199 个构建步骤。[自举收敛计划](自举收敛计划.md)
