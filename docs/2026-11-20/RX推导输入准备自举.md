# RX 推导输入准备自举

## Intent · 目标

把正式 RX 项目推导前的输入准备迁入 RX/ZX。文件装载完成后，统一组织模块复核、类型入口补齐、ZX 依赖闭包、编译库引用和诊断源文登记。

## Data · 调用路径

普通 RX 编译与库、Gateway 服务的分析调用 `rx/analyze.zig`。它原先在 Zig 中完成整个推导前流程。`check-rx` 和语义 lint 也使用其中的类型入口收集，`check-rx` 还调用编译库引用检查。三条路径现在调用共用的 Source 规则。

```mermaid
flowchart LR
    Load[装载 RX 文件] --> Validate[复核已登记 Module]
    Validate --> Types[收集包中公开的类型源码]
    Types --> Roots[登记 ZX 根及预读文本]
    Roots --> Dependencies[装载并核对传递依赖]
    Dependencies --> Compiled[收集编译库并验证可执行入口]
    Compiled --> Infer[项目推导]
    Infer --> Evidence[登记诊断源文]
```

## Edges · 顺序与所有权

`Type.from` 按 Module、Store 的顺序扫描各文件，并保留每个文件内的逆向引用索引。编译库 `Call.module` 只扫描 Module，保留原有正向索引。两条路径借用同一类索引视图，仍按阶段顺序独立执行，保留第一条错误及原位置。

ZX 根入口的路径索引先完整登记，遍历时继续共享预读的文本。没有包作用域时保留传递依赖的物理文件复核。已经处理的根继续复用同一份依赖闭包。只在推导成功后追加诊断源文。阶段作用域在失败和成功时均释放，推导结果成功时转移其 arena 所有权。

```mermaid
flowchart LR
    References[借用已解析引用] --> TypePass[类型路径与文件核对]
    References --> CompiledPass[可执行导出核对]
    TypePass --> Text[借用源码字节]
    CompiledPass --> IR[借用编译库内容]
    Text --> Prepared[准备好的推导输入]
    IR --> Prepared
    Prepared --> Result[转移推导结果和源码描述符]
```

仍由 Zig 提供文件观察、路径索引和缓存存储、编译器推导 API 及其结果生命周期。单独的 Store 类型签名检查和 `check-rx` 的函数检查流程仍需迁移。
