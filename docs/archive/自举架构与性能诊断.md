## Answer · 问题、修复与验收

### A · 常驻 RX 缓存以整批为失效和保留单位

**机制。** `generate_parser.zig:167` 调用 `resident.modules.parse`。只要包摘要或任一输入发生变化，`resident/modules.zig:22–42` 便为整组输入调用 `rx.parseModules`，将旧 `TextResult` 加入 `replaced`。在有效输入上，`rx/text.zig:60–98` 逐文件解析 XML 后再校验集合。分析器复用 5,250 个模块与 XML 层整批重解析可以同时发生。历史只要借用上一轮任一模块、frame 或签名，就连同旧 epochs 保留。预算只累加分析和输入 arena 的 `queryCapacity()`，在下次请求开始检查 3 GiB 阈值。文件旧文本、RX 历史结果、ZX 替换结果以及 emission 的保留容量各有自己的所有者和释放点。错误请求也可能已经替换文件或解析结果，却没有成功发布新分析来触发历史回收。[解析与替换](../packages/compiler/build/resident/modules.zig) · [逐文件 XML 与全图校验](../packages/compiler/src/rx/text.zig) · [常驻生命周期](../packages/compiler/build/resident/state.zig) · [旧源码](../packages/compiler/build/resident/files.zig) · [ZX 解析缓存](../packages/compiler/src/zx/modules/parse_cache.zig)

**改法。** 先记录各 owner 的活跃字节、保留容量、旧世代数、XML 实际解析数，覆盖成功、失败、还原。让未变文件复用拥有源码的解析结果；按路径、来源和内容版本安装新值，包配置与跨模块依赖另作图失效判断。对可变的 schema 标记、包作用域和诊断位置，明确哪些可以共享，哪些需要新的一版。让新分析显式持有实际引用的世代，最后一个读者退出后释放旧值。增量演进时可先对未被成功分析引用的替换版本及时回收并补齐预算计量，再收细成功请求的所有权。预算兜底保留，避免每次编辑强制清空导致全量重新分析。emission 页复用有降缺页的用途，单独量测高水位后决定限容。

**验收。** 用同一 725 入口运行上面的编辑序列，延长重复编辑以区分预热和持续斜率，并覆盖现有错误恢复、改依赖、改包和无修改场景。对于单文件文本改动，未变文件的 XML 重新解析数应为零；图校验仍能拒绝环、丢失引用并还原位置。列出请求后 RSS 与各 owner 的稳定区间、最大值、回收时点，同时核对推导复用、墙钟和干净产物。连续失败不能积攒无读者的旧版本。

### B · 冷生成文本在 printer、工作线程、bundle、缓存之间重复复制

**机制。** 正式 printer 借用结构化 AST 列，输出却先落在以节点分配器为 backing 的临时 arena，再由 `allocator.dupe(u8, output)` 整段复制到调用者。批量函数生成把这份结果放入 worker arena；随后按偏移分配 bundle 大缓冲并复制每份文本；有生成缓存的未命中项再由 `Cache.put` 拷贝一次。对确实走完该路径的 L 字节，原始打印之后有三次整段复制。工作线程结果在整批结束前仍活跃。命中分支会在更新缓存前复制，这是为了旧记录替换时输出仍有效。[printer](../packages/genz/src/printer/host.zig) · [worker 与缓存发布](../packages/compiler/src/backends/zig/function_sources.zig) · [批量分配](../packages/compiler/src/backends/zig/function_sources/publication.zig) · [缓存拥有](../packages/compiler/src/backends/zig/cache.zig)

**改法。** 先让结构化 printer 的输出拥有者和遍历 scratch 可分别指定，或转移最终字节缓冲。随后让 worker 交出仅含返回字节的缓冲；如确需连续 bundle，可直接写最终位置或只保留一次有实测价值的紧凑化。检查后台写盘、旧 bundle 与缓存淘汰的最后读者，再决定缓存可否接管或共享不可变文本。不得将 worker 整个 arena 挂进长寿命缓存，也不得为了节省一次输出复制而默认增加完整的计长遍历。

**验收。** 分别对冷 miss、暖 hit、替换旧记录、后台写者和 OOM 路径统计每层复制字节、同时存活容量、emit CPU 及 RSS。printer → worker 的纯接管复制应消失，剩余每次整段复制要给出生命周期依据。保持输出顺序、Zig 逐字节与可独立释放的返回契约，继续仅由结构化 printer 输出 Zig。

### C · 所有权已按入口分析，摘要初始化仍按所有函数重复

**改法。** 记录每次入口修改的行与槽，比较实际触达比例。优先在真实修改时记录脏行，下一个入口只重置上一入口写过的部分；若密集输入占多数，对比现有连续清空的成本。保留未知事实的初始含义、递归收敛、并发可见性与原入口发布顺序。与此同时，核实当前 Zig 宿主的 settle/demand/plan 阶段分派；将受此次修改的入口初始化和发布选择放在 RX，内聚的不动点/worklist 循环保留在 ZX，平台线程只负责执行。全仓唯一性迁移仍在原 goal 中。[现行不动点与发布](../packages/genz/src/zx/uniqueness/root.zig)

### D · 每个生成单元按全局类型规模收费

**机制。** `functionPrepared` 先用根 Program 初始化 `names/used/cache_reads`，选择具体函数后又分配对应三张表并覆盖字段。对于共享类型文件的函数单元，类型节点虽然按需生成，`types.shared` 仍取项目全部 T 个类型，为五张 u32 节点 ID 表写入哨兵。F 个未命中函数单元累计初始化 20FT 字节；单个活跃单元的五张表是 20T 字节，还需另算 AST 和局部表。该公式描述源码操作量，实际驻留页和优化后的机器写入应单测。[函数单元选择](../packages/genz/src/zx/modules.zig) · [根工作表分配](../packages/genz/src/zx/render.zig) · [共享类型的惰性读取与全表清空](../packages/genz/src/zx/types.zig)

**改法。** 先选函数再配置局部 scratch，消除三张被覆盖的根工作表。类型表以每个 worker 为复用边界，拆开可复用存储和仅在当前 builder 有效的节点 ID。比较记录触达槽并重置与按实际占用选稀疏存储两种成本，选择较小改动；密集 types 单元可维持顺序表。禁止跨 builder 沿用旧节点 ID。

**验收。** 在 725 入口清单记录函数 miss 数、T、各表触达槽数和工作线程峰值。对冷生成、单函数重新生成、密集类型、外部 ABI 和并发输出核对阶段 CPU、RSS 及全部生成字节。根工作表的无效分配应消失，稀疏函数不得反复清空全项目的五张表。
