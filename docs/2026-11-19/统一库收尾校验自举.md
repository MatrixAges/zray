# 统一库收尾校验自举

## Intent · 目标

把源码库链接收尾中的 Store 冲突、IR 和公开接口检查交给 RX。共用编译库的结构与公开契约规则，保留各入口的校验顺序和诊断。

## Data · 正式调用链

源码库链接先检查 Store 类型冲突，然后验证完整 IR，最后调用编译库校验。编译库校验再次验证了同一份 IR 及 Store。独立校验还需要构造只在重载路径使用的空目标和映射描述符。

```mermaid
flowchart LR
    Link[源码库链接完成] --> Store[检查 Store 冲突]
    Store --> IR[核验完整 IR]
    IR --> Header[检查库头部]
    Load[外部静态库校验] --> ExternalHeader[检查库头部]
    ExternalHeader --> ExternalIR[核验完整 IR]
    Header --> Public[检查名义类型、初始化器和公开接口]
    ExternalIR --> Public
    Public -->|源码链接| Result[交付或映射诊断]
    Public -->|外部静态库| ExternalStore[核对 Store 类型]
    ExternalStore --> Result
```

## Edges · 语义与存储

源码链接先报告 Store 冲突，再报告 IR 错误，随后检查库的公开形状。磁盘工件从头部开始校验，完整验证通过后才能进入类型重映射与发布。编译库对校验失败保持原有的统一诊断。结果共享表由 Zig 提供只读视图，工作区随校验结束释放。

链接校验在进入 IR 与公开契约阶段时分别记下进度，便于将原生读取和分配错误映射到原有诊断。成功路径不再生成未使用的已校验前缀描述符。独立校验直接调用 RX 校验入口，加载入口只处理带有效目标的请求。

源码库的导出行由此前的 [RX 发布流程](源码库公开导出写回自举.md)写入。本批衔接其后的库校验，逐输入的类型、函数和 Store 初始化器装载仍由外层链接流程调度。

## Answer · 验收

初始 Zig seed 与已验收的 Source 引导器均生成三个校验入口。两者的公开入口包装一致，内部生成文件存在差异。用初始 seed 的真实构建依赖执行仓库的六项 Store 链接测试，身份复用、正反输入顺序的类型冲突和分配失败全部通过。

正式 CLI 和编译器的统一库链接、编解码、重放、初始化器、导入、原生链接、库发布及运行回归通过 153 个构建步骤，其中重新执行了 55 项 Zig 测试。公开工件的损坏内容拒绝和旧产物保持也通过。

候选与直接对照 `2e82690c1` 使用同一 `7c9b225c3` Source 引导器，执行 Source 分析和生成。macOS arm64、Zig 0.17.0、ReleaseSmall，关闭磁盘生成缓存。源码发布沿用固定对照 `6e0cf529f`，编译库重发沿用 `fe2b69bd9`。版本交错运行，对比同一输入和生成文件。
