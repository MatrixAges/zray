# 引导目录文件路由与层级装配自举

## Intent · 目标

将引导器扫描目录后的文件路由、缓存探测选择和记录装配迁入 ZX。保留广度优先顺序、文件路径身份、缓存复用和工作线程临时内存的释放时机。

## Data · 正式调用链

`source_collection.scan` 为每层目录调用宿主读取目录项。此前每个文件先调 Source 构造逻辑路径，再调另一个入口判断是否查询缓存，Zig 随后逐条装配返回记录。新的文件路由在一个入口内完成后缀判定、路径和相对路径登记以及缓存选择。目录的下一层仍由已有的 RX 规则决定。

```mermaid
flowchart LR
    Read[平台枚举本层目录] --> Route[ZX 决定文件种类、路径及缓存探测]
    Route --> Cache[宿主核对已保存的文件版本]
    Cache --> Lists[持有每个目录的记录]
    Lists --> Level[RX 计算下一层与容量]
    Level --> Publish[ZX 按目录顺序装配本层记录]
    Publish --> Release[释放本层工作线程的临时内存]
```

## Edges · 借用和副作用

目录名和文件名只在系统迭代器承诺的窗口读取。单参与者直接把逻辑路径放进调用者已有的持久区域，装配时整段转移记录。多个参与者先在各自临时区域分配路径，随后只把需要跨越线程区域寿命的路径迁到调用者区域，并用新存储建立相对路径切片。缓存返回的正文仍借用原来的存储，分类和装配均不复制正文。

```mermaid
flowchart LR
    File[路径、元数据和缓存正文引用] --> Shape[按原顺序转移记录]
    Shape --> Owner{路径已属于最终区域}
    Owner -->|是| Keep[保留两种路径的切片]
    Owner -->|否| Copy[复制路径一次并重建相对切片]
    Keep --> Result[交付扫描记录]
    Copy --> Result
```

文件系统访问、Darwin 批量属性记录的解码、线程及 arenas 的调度仍使用原 Zig 宿主。初始 seed 继续支持等价的目录路由和装配。

## Answer · 验收

候选和下一代引导器均通过 25 个构建步骤。两代引导器的 86 个分区产物逐字节一致，输入戳除外。初始 seed 的 lexer 构建通过 14 个步骤，模块生成和解析缓存回归通过 39 个步骤及 37 项 Zig 测试。

多根目录样本的 8 个产物在两代引导器之间逐字节一致，覆盖模板编辑、恢复、重复模板路径和无变化复用。常驻热启动样本在同一深度有两个含源码的目录，首次发布复用了热启动分析。随后在常驻进程中编辑并恢复模板，各次产物与独立生成一致。外部接口样本保留了目录内接口和直接物理路径访问，缺失后能恢复。lexer 源码也完全一致。

固定 735 个入口、16 个分区，macOS arm64、Zig 0.17.0、ReleaseSmall。三套工具均由 Source 引导器构建，执行 Source 分析与生成。交错三轮取中位数，另在每轮中精确计时六次无变化请求。相邻两代的 11,758 个文件及 v18 唯一性缓存载荷逐字节一致，输入戳随引导器身份变化。固定基线的历史产物差异与上一阶段完全相同。
