# 生成缓存调度与缓冲留存自举

## Intent · 目标

把生成缓存的查找、登记、写回以及常驻目录切换规则迁到 RX/ZX。保留存储格式、分配器归属和后台写入期间的缓冲寿命。

## Data · 正式调用链

`backends/zig/cache.zig` 供 CLI 和引导器共用。缓存封包和批量命中分类已经由 Source 执行。此前单条查询、等待批次和开始批次的动作，以及旧缓冲留给哪个批次，均由宿主决定。

```mermaid
flowchart LR
    Key[查询生成键] --> Route[ZX 选择内存、磁盘或缺失]
    Route --> Buffer[借用或装载源码缓冲]
    Buffer --> Replace[ZX 确定登记与排队位置]
    Replace --> Queue[提交缓冲引用和缓存记录]
    Queue --> Schedule[RX 编排完成上批并启动或同步写入]
    Schedule --> Complete[等待平台写入后结算结果]
```

## Edges · 所有权和失败次序

写回队列收集缓冲引用。替换缓存项时，由 ZX 判断旧缓冲是否仍属于尚未开始的写回队列。队列继续持有的缓冲在对应写回结束后释放，其他旧缓冲可在替换时释放。空队列直接返回，未发生替换的批次跳过释放位置扫描。创建线程失败时由宿主同步执行该批写入。

```mermaid
flowchart LR
    Request[常驻请求给出缓存目录] --> Select[ZX 选择复用、打开或替换]
    Select -->|替换| Join[完成旧缓存的后台写入]
    Join --> Open[宿主打开新缓存]
    Select -->|打开| Open
    Open --> Trace[按 ZX 规则保留分析追踪]
    Select -->|复用| Use[使用已打开的缓存]
    Trace --> Use
```

缓存使用存储对象已经持有的目录名。Zig 继续提供文件系统、线程、分配器和实际资源释放，同时沿用原有的逐条错误记录。初始 seed 执行等价的调度规则。

## Answer · 验收

初始 seed 通过 14 个构建步骤，Source 引导器通过 25 个步骤。两代引导器生成同一份新规则清单，排除输入戳后 72 个文件逐字节一致。常驻请求在两个缓存目录间切换，确认旧目录的后台记录都能读回，并将损坏的磁盘记录重建为原内容。另通过实际缓存 API 连续替换同名条目，在写入开始前及后台写入期间保留对应缓冲，三个不同键都能从磁盘读回正确内容。

生成缓存、生成产物执行和原生对象 ABI 回归通过 77 个构建步骤、23 项 Zig 测试及 4 项独立执行检查。固定的 735 入口清单上，候选与上一阶段的 11,758 个文件逐字节一致，排除环境输入戳，唯一性缓存载荷哈希相同。三套工具均由 Source 引导器生成，运行时采用 Source 分析与生成。以下是 macOS arm64、Zig 0.17.0、ReleaseSmall 下三轮交错运行的中位数。范围限于生成器。

| 场景               | 固定基线墙钟 / CPU | 上一阶段墙钟 / CPU |  候选墙钟 / CPU |
| ------------------ | -----------------: | -----------------: | --------------: |
| 冷生成             |    2.87 / 12.51 秒 |    2.57 / 12.23 秒 | 2.62 / 12.29 秒 |
| 热生成             |     2.20 / 8.47 秒 |     2.01 / 8.30 秒 |  1.97 / 8.29 秒 |
| 输入和输出均未变化 |     0.04 / 0.03 秒 |     0.04 / 0.03 秒 |  0.04 / 0.03 秒 |

冷生成首次粗采样的进程树 RSS 中位数由 696.5 MB 升至 708.9 MB，系统峰值 RSS 由 737.3 MB 升至 790.0 MB。使用同一输入及配置追加四组进程内存高频交错对照，RSS 采样峰值由 719.5 MB 降至 716.1 MB，内存实际占用峰值由 721.9 MB 降至 714.2 MB，系统峰值 RSS 由 727.1 MB 降至 719.5 MB。初次看到的增幅未稳定复现。固定基线冷生成系统峰值为 921.3 MB。
