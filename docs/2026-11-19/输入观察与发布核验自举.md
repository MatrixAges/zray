# 输入观察与发布核验自举

## Intent · 目标

贯通 CLI 的依赖登记、源码记录、观察快照和发布前核验。迁移登记与对照规则，保留进程中的输入文件观察边界、诊断顺序、产物发布门禁和已有的版本复用。

## Data · 正式调用链

`Inputs.add`、`addDirectory` 和 `record` 服务于项目装载、库构建、原生依赖、后端响应及监听恢复。原来路径登记和版本复用在 Zig 中驱动。现在 RX 选择重复登记、复用已验证文件、读取新状态或升格目录观察。后端发布、库发布和监听共用同一份输入模块，测试也通过该模块核验真实输入。

`Snapshot.unchanged`、`verifyVersions` 和 `poll` 共享 RX/ZX 扫描。发布前重新读取内容并校验物理路径，缓存开启时为成功匹配的文件记录版本。监听轮询只有在已知版本和物理路径都匹配时才跳过内容读取。首次变化即返回。记录源码时仍以实际提交给编译器的字节计算摘要。

```mermaid
flowchart LR
    Inputs[源码、库及后端输入] --> Admit[RX 检查输入登记]
    Admit --> Reuse{可以复用已核验版本}
    Reuse -->|是| Borrow[借用前次文件状态]
    Reuse -->|否| Read[RX 按文件类型读取状态]
    Borrow --> Capture[写入独立快照]
    Read --> Capture
    Capture --> Verify[RX 和 ZX 核验内容与物理路径]
    Verify --> Publish[发布产物和可复用版本]
    Verify --> Reject[检测到变化即停止发布]
```

## Edges · 数据所有权

文件、目录、路径解析、排序、SHA-256、版本元数据和 arena 由 Zig 宿主持有。文件和目录状态等值规则由 ZX 执行，借用两侧已有摘要和路径。运行时保留文件内容和工作区目录项的原有读取规则，读取后释放单条快照比较的临时空间。目录哈希仍由现有宿主实现生成。

完全相同的已规范化路径在重复登记时直接查表，减少路径解析和临时分配。快照拥有自己的路径副本，避免引用已释放的本轮登记或上次观察区域。

```mermaid
flowchart LR
    Current[本轮路径和观察状态] --> Rows[快照记录拥有需要留存的路径]
    Previous[上一轮物理路径与已核验版本] --> Lookup[按精确路径借用]
    Lookup --> Current
    Rows --> Scan[核验使用单条临时区]
    Scan --> Match{状态一致}
    Match -->|是| Save[按调用模式记录版本]
    Match -->|否| Abort[报告输入变化]
```

## Answer · 验收

最终八组回归通过，共 108 个构建步骤、18 项 Zig 测试和 68 项 Node 检查。覆盖库发布、后端发布、ZX 与 RX 监听、缺失原生头文件、已安装原生包、失败后恢复及已发布产物保护。另对正式 CLI 验证保留 mtime 的原地编辑和原子替换，应用输出随实际内容更新。

首轮 ReleaseSmall 回归在哈希表首次写入后暴露空条目指针。登记现在使用直接返回的键、条目及命中标志，再把结果交给后续阶段。小范围复现通过首次登记、重复登记、目录观察升格和版本核验。正式库发布复现也成功，输出与直接对照逐字节一致。

初始 seed 和 `7c9b225c3` Source 引导器分别生成同一份观察清单。42 份生成产物中 40 份逐字节一致，其余只涉及局部临时变量名。观察规则未在快照的逐条分派或对照中增加堆分配，仍按原有方式分配快照与路径数据。

### 输入登记专项对照

继续使用两组各 1,000 个稳定文件，分别约 3 KiB 和 32 KiB。每轮初始快照核验后登记 24 次，并逐项比较摘要、物理路径和文件状态。ReleaseSmall 两版交错运行，去掉预热取七轮中位数。墙钟及 CPU 覆盖进程，包含初始核验和正式登记。基线工具来自 `037081097`，其登记、快照和目录实现与直接对照 `00f71709c` 相同。

### 正式库监听对照

沿用 16 个公开 RX 入口与 49 个共享 ZX 依赖。大源码组在 ZX 文件中增加约 122 KiB 注释。macOS arm64、Zig 0.17.0、ReleaseSmall，三套 CLI 都由 `7c9b225c3` Source 引导器构建，执行 Source 分析和生成。固定对照仍为 `689d854f8`，直接对照为 `00f71709c`。首轮预热后每版交错运行三轮，每轮编辑同一个依赖三次。编辑墙钟包含轮询等待，CPU 为编辑窗口内监听进程的采样差，峰值 RSS 覆盖整轮。每个场景最终发布的 70 份文件在三版之间逐字节一致。

| 场景     | 首次发布墙钟秒（固定 / 直接 / 候选） | 单次编辑墙钟秒（固定 / 直接 / 候选） | 单次编辑 CPU ms（固定 / 直接 / 候选） | 峰值 RSS MB（固定 / 直接 / 候选） |
| -------- | -----------------------------------: | -----------------------------------: | ------------------------------------: | --------------------------------: |
| 常规源码 |                0.904 / 0.855 / 0.857 |                1.415 / 1.367 / 1.369 |                 25.89 / 24.82 / 24.86 |             69.94 / 66.91 / 66.47 |
| 大源码   |                2.777 / 2.696 / 2.756 |                1.729 / 1.600 / 1.707 |                 33.39 / 30.19 / 32.79 |            176.05 / 81.48 / 81.56 |

相对直接对照，大源码单次编辑墙钟增加 107 ms，CPU 增加 2.60 ms，峰值 RSS 增加 0.08 MB。相对固定对照，两组的墙钟、CPU 和峰值 RSS 仍较低。登记专项对照未观察到同方向的耗时增长。本阶段的性能证据覆盖输入登记及公开库监听，未复测完整自举冷构建。

原始记录在 `.zig-cache/verification-tmp/watch-observations/`，包括 `final-regression.log`、`probe.log`、`edited-tests.log`、`generation-parity.log`、`registration-comparison.json` 和 `parse-reuse-comparison.json`。
