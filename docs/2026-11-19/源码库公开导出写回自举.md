# 源码库公开导出写回自举

## Intent · 目标

让源码库链接中的公开接口发布由一条 RX 流程执行。覆盖 ZX 与 RX 入口、类型库、具名转导出、公开常量与可执行模块端口。保持导出顺序、错误顺序和发布文件的字节内容。

## Data · 正式入口

`zxc build pkg.yaml --mode lib` 在完成源码分析后调用 `library.link`。旧宿主依次调用独立的公开类型、常量和成员入口，再复制名称及路径并组装导出记录。实际写回现在由 `library/publication/publish.rx` 负责。旧的公开类型与成员规则继续在这条流程中执行。

编译库重载走既有的[编译库共享表写回](编译库共享表写回自举.md)。源码库对照沿用[公开接口与函数成员发布](../2026-11-18/库公开接口与函数成员发布自举.md)的混合库和转导出输入。

```mermaid
flowchart LR
    A[源码分析与函数链接] --> B[借用公开声明和导出表行]
    B --> C[映射输入输出并发布公开类型]
    C -->|成功| D[发布常量]
    C -->|失败| E[返回原诊断]
    D --> F[发布公开及转导出成员]
    F -->|成功| G[直接填写导出行]
    F -->|失败| E
    G --> H[共享库校验与产物输出]
```

## Edges · 借用与失败顺序

Zig 提供只读源列和可写结果列。RX 先校验和发布类型，再发布常量及成员。ZX 在各阶段成功后复制公开名称与路径，将新生成的类型、常量、成员切片装入结果行。切片描述符按行数写入，内容沿用生成时的分配。出错时外层链接 arena 负责释放当前发布分配。

入口函数的解析和写入发生在公开接口发布之前。共享类型表、函数表、Store 初始化器和最终库验证仍由外层链接流程衔接。初始 Zig seed 沿用自己的公开接口实现。

## Answer · 验收

统一库链接、编解码、Store 初始化器、独立进程重放、编译库契约复验和正式 CLI 的库发布与消费通过 153 个构建步骤及 120 项 Zig 测试。CLI 回归覆盖源模块搬移、原生与普通库重发、公开入口、Store 调用和发布失败后的产物保留。另核对了公开字符串及整数常量的工件内容。

使用 macOS arm64、Zig 0.17.0、ReleaseSmall。直接对照为 `e326bdd43`，候选与直接对照均用 `7c9b225c3` 的 Source 引导器生成并运行 Source 分析与生成。源码库固定对照沿用 `6e0cf529f`。每轮交错执行三版 CLI，禁用生成缓存并核对所有发布文件，去掉预热后取八轮中位数。

| 五导出混合库              |          40.06 / 40.07 / 39.88 |         37.61 / 37.72 / 37.44 |              25.03 / 25.03 / 25.03 |
| 具名转导出                |             6.65 / 6.69 / 6.76 |            6.25 / 6.19 / 6.17 |                 8.77 / 8.67 / 8.67 |
| 字符串和整数公开常量      |             4.86 / 4.71 / 4.81 |            4.24 / 4.04 / 4.18 |                 7.32 / 7.26 / 7.26 |

四个场景的 95 份发布文件逐字节一致。共享依赖样本相对直接对照增加 2.26 ms CPU，峰值 RSS 中位数增加 3.38 MB。两版峰值范围分别为 90.70～102.15 MB 和 90.90～98.24 MB，候选中位数仍低于固定基线。其余三个样本峰值 RSS 中位数与直接对照一致。本批测量覆盖源码库发布，未重复计量完整编译器冷构建。
