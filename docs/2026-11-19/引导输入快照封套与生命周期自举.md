# 引导输入快照封套与生命周期自举

## Intent · 目标

让正式引导器的输入快照由 RX/ZX 负责封套、校验与复用判断。沿用已有磁盘格式和现有的文件时间判定。把旧快照解码数据和新快照序列化缓冲的寿命限制在各自的读写阶段。

## Data · 正式入口

`generate_parser.zig` 调用 `input_snapshot.zig` 读取快照并观察当前输入。此前 Zig 负责截取封套并比较校验值，把解析出的全部列保存到请求结束。记录快照时又逐个查询同样的文件版本两次。Source 已负责核对文件身份、时间边界和列形状。

```mermaid
flowchart LR
    Disk[读取快照文件] --> Frame[Source 切分封套]
    Frame --> Verify[Source 比对 Blake3 校验值]
    Verify --> JSON[解析已有 JSON]
    JSON --> Reuse[Source 核对上下文与文件事实]
    Reuse --> Digest[保存可复用摘要]
    Digest --> Release[释放读入缓冲和列]
```

## Edges · 兼容与分工

文件仍由同宽度的小写十六进制校验值与原 JSON 组成。在校验成功后才解析 JSON。读取时 Source 借用封套与载荷的切片，解码与复用检查结束后只保留 32 字节指纹。记录快照时只查询每个文件版本一次，在写回完成后释放列和 JSON 缓冲。Source 负责文件长度上限、切分、校验比较以及原有的复用规则。Zig 宿主提供文件系统观察、原子替换、通用 JSON 编解码、版本查找及 Zig 标准库 Blake3。初始种子保留等价的封套处理。

```mermaid
flowchart LR
    Versions[读取完成的文件版本] --> Columns[逐项登记快照列]
    Columns --> Encode[编码原有 JSON]
    Encode --> Seal[Source 核对大小并生成校验值]
    Seal --> Publish[原子替换快照]
    Publish --> Release[释放快照缓冲]
```

## Answer · 验收

初始 seed 通过 14 个构建步骤。使用 `c7608fae3` 的 Source 引导器构建候选通过 25 个步骤。两代引导器生成同一份快照规则清单，排除本机输入戳后 105 个文件逐字节一致。

保留旧版快照的逐列文件事实，仅替换与生成器二进制绑定的上下文和指纹并重算校验值。候选连续读取时保留快照时间戳。截断、错误校验值、超限、损坏 JSON、错误上下文、非法指纹、无效列长度和未来读取时间都会回退并修复文件。修改源码再恢复，两版生成物一致。常驻引导器在快照损坏后修复，下一次请求直接复用，生成树与独立生成一致。

### 性能

macOS arm64，Zig 0.17.0，ReleaseSmall，16 分区。固定 735 个入口，固定基线、上一阶段和候选都通过对应 Source 引导器构建并执行 Source 分析与生成。三版交错运行，各取三轮中位数。上一阶段与候选的 11,758 个生成产物及 v18 唯一性缓存载荷逐字节一致。

| 场景与指标                 | 固定基线 | 上一阶段 |   候选 |
| -------------------------- | -------: | -------: | -----: |
| 冷生成墙钟（秒）           |     2.80 |     2.53 |   2.53 |
| 冷生成 CPU（秒）           |    12.28 |    12.13 |  12.10 |
| 冷生成进程树采样峰值（MB） |   907.94 |   704.17 | 698.38 |
| 冷生成单进程系统峰值（MB） |   940.88 |   799.97 | 769.61 |
| 热重建墙钟（秒）           |     2.17 |     1.97 |   1.94 |
| 热重建 CPU（秒）           |     8.34 |     8.22 |   8.19 |
| 热重建单进程系统峰值（MB） |   934.18 |   700.55 | 696.78 |
| 无修改墙钟（秒）           |     0.04 |     0.04 |   0.03 |

峰值是整次生成的进程数据。固定输入的这组对照覆盖分析和 Zig 源码生成。原生分区编译与链接在引导器构建中另行验证。
