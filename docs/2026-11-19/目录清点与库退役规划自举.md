# 目录清点与库退役规划自举

## Intent · 目标

将原生目录展开、库管理清单采集及旧产物退役规划接到 RX/ZX 正式路径。维持符号链接、文件诊断及发布前输入核对的行为。

## Data · 正式路径

原生资源和包含目录共用 `resources.files`。库写出先采集管理清单，随后由 `publication.library` 验证并规划退役。三处复用已有目录游标和标准库文件操作。

```mermaid
flowchart LR
    Native[原生目录与包含目录] --> Walk[借用目录游标]
    Generated[已暂存的库文件] --> Walk
    Walk --> Paths[ZX 选择路径并核对类型]
    Paths --> Inventory[记录路径、类型或摘要]
    Inventory --> Compare[RX 规划退役]
    Prior[旧清单] --> Compare
    Compare --> Check[核对文件、物理别名、输入与摘要]
    Check --> Commit[发布后按规划清理]
```

## Edges · 顺序与数据

原生入口先登记所在路径，目录项按现有遍历顺序登记；输出沿用字节排序。库清单只纳入普通文件，继续使用流式摘要。退役先确认文字路径，再核对文件类型和物理路径。即便已经遇到匹配别名，也继续检查该轮其余目标以保留错误顺序。文件系统中间结果限于单条候选，最终退役列表仅保存通过核对的路径。

目录展开、管理清单采集和退役遍历已退出手写 Zig。Zig 适配保留标准库目录游标、文件操作、JSON、SHA-256、排序，以及哈希索引和输出列表的存储。未启用输入观察器时，原生扫描直接跳过子目录的路径拼接。

ReleaseSmall 窄验收发现，直接把游标状态地址作为只读 `opaque` 传入时，LLVM IR 会把常规更新调用标为 `readonly`，随后命中空的路径指针。改为借用栈上的指针槽，底层游标及工作区保持可写。原生目录、清单、退役和正式发布游标使用这一约定。现有 259 文件夹具在 ReleaseSmall 下完成清点和退役规划。

```mermaid
flowchart LR
    Prior[借用旧清单行] --> Scratch[当前行的路径与摘要]
    Scratch --> Alias[比较现有普通文件目标]
    Alias --> Saved[只保存通过校验的路径]
    Scratch --> Reset[下条候选复用临时区]
```
