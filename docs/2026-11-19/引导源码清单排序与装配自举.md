# 引导源码清单排序与装配自举

## Intent · 目标

让 RX/ZX 决定引导源码清单的排序和各类输入的位置。正式清单、lexer 自举和输入快照沿用相同的字节路径顺序与并列顺序，保持生成产物、诊断和缓存行为。

## Data · 正式入口

`generate_parser.zig` 和 `generate_lexer.zig` 原先在读取每个文件时由 Zig 分别登记 ZX、RX 和模板，最后再对各类型排序。输入快照另外对物理路径排序。现在宿主按根目录和发现顺序读入统一记录，将路径列和文件类别借给 Source。RX 组织统计、排序、分组。ZX 生成稳定顺序与组内位置。

```mermaid
flowchart LR
    Manifest[正式清单或 lexer 入口] --> Read[平台按原顺序读取]
    Read --> Inventory[借用路径和文本的记录]
    Inventory --> Count[ZX 统计 ZX 和 RX 条数]
    Inventory --> Sort[ZX 计算稳定路径顺序]
    Count --> Group[ZX 按组登记行号]
    Sort --> Group
    Group --> Deliver[填入精确容量的类型化清单]
```

## Edges · 数据与兼容边界

排序比较路径字节。相等时以读取顺序决定先后，保留稳定语义。清单只重排索引，宿主由索引填充 ZX、RX 和模板视图，借用原始源码和模板。完整清单继续给 ZX 绑定模板、给 RX 绑定包。lexer 保留显式的 core 路径及其原有包注入方式。快照排序复用同一个 ZX 比较规则，在原有记录空间内按置换搬动记录。

```mermaid
flowchart LR
    Observe[目录及接口观察结果] --> Columns[借用物理路径列]
    Columns --> Order[计算稳定行序]
    Order --> Permute[原地重排观察记录]
    Permute --> Snapshot[核对或写入现有快照]
```

初始种子保留等价规则用于引导。Zig 继续提供平台目录与文件 API、类型化内存视图和快照行交换。目录队列、根路径资格化和文件缓存探测属于剩余源码收集路径。

## Answer · 验收

初始 seed 通过 14 个步骤，使用上一阶段 Source 构建候选通过 25 个步骤。两版生成的 lexer 源码与同一份新清单规则的 61 个文件逐字节一致。多根清单使用 RX 入口、跨根包别名和模板资源，模板编辑改变生成结果，恢复后回到原结果。重复模板路径仍被拒绝且撤销输入戳。常驻生成器实际走只分析的启动路径，随后核对模板编辑、独立冷生成、恢复和无修改复用。

macOS arm64，Zig 0.17.0，ReleaseSmall，16 分区。三个版本由 Source 引导器生成并执行 Source 分析与生成。固定清单为 735 个入口，交错运行三轮取中位数。上一阶段和候选的 11,758 个生成文件与 v18 唯一性缓存载荷相同，输入戳随工具身份变化。

| 场景与指标                 | 固定基线 | 上一阶段 |   候选 |
| -------------------------- | -------: | -------: | -----: |
| 冷生成墙钟（秒）           |     2.86 |     2.58 |   2.60 |
| 冷生成 CPU（秒）           |    12.48 |    12.20 |  12.19 |
| 冷生成进程树采样峰值（MB） |   894.29 |   699.04 | 698.88 |
| 冷生成单进程系统峰值（MB） |   923.17 |   784.71 | 735.35 |
| 热重建墙钟（秒）           |     2.21 |     1.98 |   1.99 |
| 热重建 CPU（秒）           |     8.49 |     8.29 |   8.25 |
| 热重建单进程系统峰值（MB） |   934.53 |   697.37 | 696.42 |
| 无修改墙钟（秒）           |     0.04 |     0.03 |   0.04 |

相对固定基线，冷生成墙钟下降 0.26 秒，CPU 下降 0.29 秒。相对上一阶段，冷生成进程树采样峰值基本持平，操作系统记录的单进程峰值下降 49.36 MB。对照覆盖分析及 Zig 源码生成，分区对象及链接由引导构建另行验证。
