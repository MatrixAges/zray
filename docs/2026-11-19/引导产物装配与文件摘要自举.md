# 引导产物装配与文件摘要自举

## Intent · 目标

把引导生成器的产物目录布局、公开入口装配和清单哈希遍历迁入 RX/ZX。保留平铺与分区输出的路径、次序和复用规则。合并路径提取与摘要遍历，减少文件清单写出前的重复工作。

## Data · 正式调用链

`shared_output.zig` 使用已经自举的规则区分函数文件和支撑文件，再调用分区规划、文件清单比对和写出。原路径在 Zig 中逐段追加文件记录，生成公开模块的适配文件名，从公开入口的类型选导出面，并在分区规划后把函数文件复制进同一数组。文件写出前另有一遍逐文件哈希和一遍路径投影。

```mermaid
flowchart LR
    B[借用编译库生成结果] --> S[ZX 计算产物段位置]
    S --> A[RX 装配公共头与可选分区段]
    A --> W[ZX 决定适配器导出面并构造 AST]
    A --> P[现有分区规划及根模块渲染]
    W --> H[借用头部与函数文件]
    P --> H
    H --> M[批量产生路径和内容哈希]
    M --> D[查询变更并发布清单]
```

## Edges · 顺序与生命周期

平铺与分区模式使用相同的公开入口装配规则。常量入口只导出已有常量命名空间，普通入口沿用各自可用的签名。适配器继续通过 genz AST 和统一 printer 生成。

头部和函数段保留各自的存储，发布逻辑用同一逻辑索引访问。路径和内容只借用原切片。哈希沿用清单原哈希算法，每批处理至多 32 个相邻文件，两个段之间没有交叉批次。宿主在并行工作结束后才释放输入。

```mermaid
flowchart LR
    H[按既定次序借用头部文件] --> Marks[在同一遍历填充路径与哈希]
    F[按既定次序借用函数文件] --> Marks
    Marks --> Compare[复用既有清单比对规则]
    Compare --> Paths[创建已变化文件的父目录]
    Paths --> Files[写出变更文件及清理旧文件]
    Files --> Ledger[发布文件清单]
```

文件系统、并发调度与 allocator 仍由 Zig 提供。渲染任务的派发和发布事务的总调度仍在 Zig 宿主中。初始 seed 保留等价的手写装配。

## Answer · 验收

候选 Source 引导器通过 25 个构建步骤。使用候选重新构建下一代引导器，通过 27 个步骤。下一代独立生成的 114 个文件逐字节一致，排除输入戳。初始 seed 的 lexer 构建通过 14 个步骤。模块生成回归通过 32 个步骤和 23 项 Zig 测试。单独检查了仅导出常量的项目，无函数文件时的平铺及 16 分区产物也与上一阶段一致。

相邻两代引导器分别验证了平铺和 16 分区输出。完整产物各有 44 和 114 个文件，精简产物各有 8 和 44 个文件，清单与这些产物均逐字节一致，输入戳另行检查复用命中和失败失效。无变更请求和内容未变化的文件保留修改时间。删减入口后清除已登记的旧文件，保留清单外文件。缺失清单与模拟写出失败均可恢复。真实常驻进程从完整切到精简，再切回完整，各次均匹配独立生成。

使用 macOS arm64、Zig 0.17.0、ReleaseSmall、16 个分区。长期基线、上一阶段和候选工具均由 Source 引导器构建，使用 Source 分析和生成。固定 735 个入口，三轮交错运行取中位数。相邻两代的 11,758 个文件及 v18 唯一性缓存载荷逐字节一致，输入戳除外。与长期基线的历史产物差异与上一阶段相同。
