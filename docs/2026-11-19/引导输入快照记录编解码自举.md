# 引导输入快照记录编解码自举

## Intent · 目标

把引导输入快照的记录布局、读写、长度校验和文件事实比较交给 RX/ZX。无变化请求直接比较磁盘记录和当前观察，省去 JSON 解码和按字段分配列表。

## Data · 正式入口

正常写入请求经 `generate_parser.zig` 进入 `input_snapshot.zig`。快照命中时，已校验的文件事实允许跳过模板展开、RX 解析和生成。旧实现要先把整个 JSON 解析成若干列，再交给 Source 判断。

```mermaid
flowchart LR
    Request[引导请求] --> Observe[观察目录和接口文件]
    Observe --> Read[读取快照并校验封套]
    Read --> Compare[ZX 逐条比较磁盘记录和当前观察]
    Compare -->|匹配| Stamp[核对输出戳]
    Compare -->|变化或损坏| Generate[继续装载和生成]
    Stamp -->|过期| Generate
    Generate --> Save[保存实际读取的文件版本]
```

## Edges · 格式与生命周期

保留 Blake3 封套、大小上限和原子写入。记录头含版本、上下文、原始输出摘要和文件数。记录逐条保存路径、文件身份、修改和状态变更时间，以及实际读取时间。引导器身份已经隔离各版快照，格式错误仍按未命中处理。文件名采用原始字节，解析时只借用磁盘缓冲。初始 seed 保留其已有 JSON 路径。

```mermaid
flowchart LR
    Facts[排序后的文件事实] --> Size[ZX 计算磁盘长度]
    Size --> Buffer[预留最终缓冲]
    Facts --> Versions[借用已读文件版本]
    Versions --> Encode[ZX 按记录顺序写入]
    Buffer --> Encode
    Encode --> Seal[校验并原子替换文件]
    Seal --> Free[释放写入临时存储]
```

## Answer · 验收

多根目录样本覆盖跨批次文件记录和带引号的路径。候选读取的路径、inode、大小和两类文件更新时间与旧 JSON 逐项一致。模板编辑与恢复、重复模板路径、内外部接口及缺失接口恢复得到一致的生成文件。常驻进程的初次发布、模板变动、恢复及无变化复用与独立生成一致。

截断头部、错误格式、错误上下文、记录数不符、截断记录、路径长度越界、路径变化、inode 变化、读取时间在未来、尾部多余数据和错误校验值均被拒绝。修复快照时复用已有生成产物。样本的快照从 27,011 字节缩到 23,227 字节，减少 14.0%。

候选和下一代引导器都通过 25 个构建步骤。两代对同一批入口生成的 103 个分区文件逐字节一致，排除输入戳。初始 seed 的 lexer 与旧快照入口通过 21 个构建步骤。模块生成和解析缓存回归通过 39 个构建步骤及 37 项测试。

固定清单有 735 个入口和 16 个分区，环境为 macOS arm64、Zig 0.17.0、ReleaseSmall。三套工具由对应的 Source 引导器生成，运行 Source 分析与生成。交错三轮取中位数，每套工具另精确计时 18 次无变化请求。
