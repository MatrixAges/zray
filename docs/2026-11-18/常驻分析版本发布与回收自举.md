# 常驻分析版本发布与回收自举

## Intent · 目标

将常驻生成器的分析前驱选择、编辑记录和发布决策迁入 Source。保持依赖变化时重新分析、旧分析借用有效、失败请求保留上次成功结果，以及恢复旧输入时释放被替代版本的行为。

## Data · 实现依据

`f588225f6` 已把文件与解析索引及 RX 模块比较迁入 Source。常驻 `state.zig` 仍调用 `revision.zig` 检查路径和正文，然后在 Zig 中逆向遍历版本，并在发布时计算改动行。现在 `choose.rx` 依次检查项目形状、RX 路径和 ZX 输入，再由 `parent.zx` 选择前驱。它沿可比较的祖先回退，遇到与本轮编辑重叠的历史记录时选用其前一版，直到无法继续比较的版本边界。

```mermaid
flowchart LR
    Request[输入形状、路径、文本、摘要] --> Admission[Source 校验同一输入范围]
    Admission -->|匹配| Select[Source 检查编辑重叠并选择前驱]
    Admission -->|范围变化| Latest[从最近的成功分析开始]
    Select --> Analyze[执行分析]
    Latest --> Analyze
    Analyze --> Decision[Source 决定恢复、保留前缀或释放历史]
```

宿主通过只读列借出现有的固定摘要与可空行号列表。选择阶段可直接访问历史记录，无需组装临时摘要表。成功发布时，改动行由 `changes.zx` 对选定前驱和当前输入的摘要进行比较。空编辑列表可以继续沿父版本查找。缺失编辑列表表示跨越输入或依赖形状边界。

```mermaid
flowchart LR
    Result[分析成功] --> Plan[Source 发布计划]
    Plan -->|输入已恢复| Restore[恢复旧 RX 批次并释放后继]
    Plan -->|提交新结果| Reserve[生成编辑列表并预留容量]
    Reserve -->|分配成功| Drop[释放已失效的历史]
    Drop --> Keep[转移分析及输入 arena 的所有权]
    Reserve -->|分配失败| Retain[保持旧版本可用]
```

## Edges · 边界

前驱、编辑行和发布方式由 RX/ZX 决定。宿主持有 arena、解析结果和 RX 批次的引用计数，按计划释放内存。旧分析及其源码的借用约束沿用原来的发布顺序。初始 Zig seed 保留同样的比较和选择规则，供独立引导使用。

## Answer · 验收

初始 seed 的 14 个构建步骤通过，Source 引导器的 25 个步骤通过。两个相邻 Source 阶段生成同一份前驱选择与发布窄清单，排除输入戳后逐字节一致。`test-rx-inference`、`test-rx-watch` 和 `test-parse-cache` 通过，共 70 个构建步骤、152 项 Zig 测试。

常驻引导器分别交替修改两个 RX 文件，以及对四个 RX 文件做多轮混合修改。两版每轮的分析、复用和保留版本数一致，恢复后均回到单一历史版本和初始产物。另一组在有效依赖与替代依赖间切换，逐轮与相同输入的冷生成比较，并验证依赖缺失、恢复和无改动请求。

### 性能

在 macOS arm64 上使用 Zig 0.17.0、ReleaseSmall、16 分区。相邻两版引导器均由 Source 构建并运行 Source 前端与生成器，固定基线沿用早先的声明准备引导器。固定 735 入口的冷生成与热重建交错运行三轮，取中位数。相邻两版的 11,758 个生成文件及 v18 唯一性缓存载荷一致。

| 场景与指标             | 固定基线 | 上一批 |   候选 |
| ---------------------- | -------: | -----: | -----: |
| 冷生成墙钟（秒）       |     2.87 |   2.58 |   2.59 |
| 冷生成 CPU（秒）       |    12.45 |  12.17 |  12.17 |
