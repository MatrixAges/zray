# RX 推导类型登记与可空查询自举

## Intent · 目标

将类型登记表与推导节点的同步写入、批量登记的进度、可空保护与类型提示的取值策略迁入 Source。登记、赋值、解构选择、节点、可空与统一等直接相关部分共 34 个 Zig 文件、3,365 行；按已退出正式入口的职责验收。

## Data · 调用链

正式入口通过图的 known 方法登记单个已知类型，选择已声明对象的字段时用 registerMembers 登记全部成员。原实现对尚未登记的每个成员返回 Zig，重复获取图节点列、创建节点并更新哈希表。可空保护只拆一层，提示允许持续查找，赋值的载荷拆解有深度限制。

```mermaid
flowchart LR
    A[单个类型或有序成员] --> B[借用类型表和节点空闲列]
    B --> C[ZX 查找与批量登记]
    C -->|新增的前缀| D[发布行范围与源位置]
    C -->|容量不足| E[扩容并重新借用]
    E --> B
    F[保护或发生赋值的推导节点] --> G[RX 选择可空查询策略]
    G -->|缺少已知节点| A
```

## Edges · 边界

重复成员复用同一编号；发现非法类型或扩容失败时，已完成的合法前缀仍然一致。只为实际缺失的类型扩容，类型和成员数组只借用，扩容后重新取视图。保留初始 seed、错误源位置和可空深度的边界行为。

## Answer · 验收

核对旧工具与候选的自生成结果、RX 推导和所有权回归，并以实际输入和固定清单对照开销。

### 正式调用链

- 单个已知类型、对象选择的全部声明成员、赋值及约束类中的可空载荷，使用同一登记入口。Source 直接在预留列中写入节点形状、父节点和哈希槽，按原顺序分配编号。重复成员命中现有节点。宿主按完成的行区间发布源位置和约束默认值。
- 表满时，宿主一次分配容纳三列的连续存储。Source 先清空占用标记，再把原表中的有效项重新散列到新表，完成后交还旧存储。普通插入和查询使用零容量分配器执行。成员、类型表、已有图节点均通过视图读取。
- RX 选择单层保护查询或连续载荷查询。后者的 ZX 原子函数决定类型提示和有界拆解的返回值。遇到尚未登记的声明可空链时，登记入口可在一次调用内处理多个子类型。遇到已经登记的子类型就回到图中查找其当前代表，保留统一后的语义和错误位置。
- 宿主继续持有图与索引的存储，处理分配失败、行范围发布和诊断。初始 Zig seed 继续使用原生推导。其余图构造、赋值和统一逻辑仍在后续自举范围中。

### 核验结果

上一阶段的 Source 工具构建了本次候选，候选再以 Source 分析和生成同一份 771 入口清单。两次生成的 13,059 个文件逐字节相同，忽略与工具身份有关的输入戳。初始 seed 及 RX 检查通过 39 项，RX 推导、并行推导、属性、项目 CLI 和库链接通过 437 项。仓库 RX 格式检查通过，本批改动的 11 个 RX/ZX 文件与格式化输出一致。

512 个不同成员类型与 512 个重复成员类型分别对照，两版各生成 41 个相同产物。三轮交替样本中，不同成员的冷生成墙钟中位数均为 0.02 秒，重复成员均为 0.01 秒。声明可空深度 1、64、255 时，两版每组 44 个产物相同；深度 256、257 时，两版均在 RX 第 2 行第 29 列返回相同深度诊断。

### 生成开销
