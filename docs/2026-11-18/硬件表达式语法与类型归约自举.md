# 硬件表达式语法与类型归约自举

## Intent · 目标

把符号模型到硬件图的 SMT 项语法、操作数个数、字面量和结果类型迁入 Source。沿用现有节点序、子项缓存、源位置和公开图类型。

## Data · 依据

`hardware.generate` 从符号定义、返回值和安全条件三个位置调用 `Terms.parse`。旧递归读取空白、括号、符号和十进制数，子项先于父项进入图。变量优先于同名布尔字面量。完整子项按源文本字节去重，数字和类型越界在发布前拒绝。

## Edges · 边界

沿用 64 MiB 输入、512 层嵌套、100,000 个节点和 256 位类型的上限。解析时直接读取输入，递归只保存当前节点的操作数。公开 Zig 联合、节点数组和已有名称映射继续使用原有存储。

## Answer · 验收

用既有硬件资源、错误输入、独立逻辑求值及时序仿真覆盖正式入口，和上阶段对照 RTL 与诊断字节。沿用常规及增长图工作负载量取 CPU、墙钟、进程峰值和分配量。

```mermaid
flowchart LR
    A[符号定义与输出] --> B[读取词和项头]
    B --> C[解析所需的子项]
    C --> D[检查闭括号并推导结果类型]
    D --> E[复用或写入节点]
```

```mermaid
flowchart LR
    A[借用的 SMT 字节] --> B[词的起止位置]
    B --> C[变量表与文本缓存]
    C --> D[原图中的节点编号]
    D --> E[操作数类型与父节点]
```

## 实现与边界

`read.rx` 连接分词、项头分类、位向量字面量和扩展算子的读取。词记录保存源位置和借用的字节切片。十进制溢出、位宽、操作数个数、布尔类型与位向量类型的规则由 ZX 执行。二元操作沿用上一阶段的操作符表和结果类型规则。

正式入口中的 Zig 仍负责深度与资源上限、递归访问子项、查询变量和缓存、装配现有硬件节点联合。旧解析器留给初始 seed。缓存先预留空间，节点追加成功后再公布编号。

迁移同时修复了普通整数 `loop` 结果被生成成指针解引用的问题。Source 和初始 seed 的选择规则对齐，只对按指针表示的对象或元组发出该解引用。完整清单中曾观察到以起止位置表示的词需要临时分配。现有词视图直接借用原输入；生成的分词和解析函数没有堆分配，公开的按值入口直接写出结果。宿主按原有错误路径传播分配失败和无效输入。

## 正确性

将上一阶段的 Source 引导器生成的本阶段工具，与初始 Zig seed 构建的本阶段工具，分别用于生成四个硬件入口。两者都分析 20 个模块。排除本机输入标记 `.zxc-inputs`，31 个生成文件逐字节相同。相对上一阶段的正式后端，常规程序的 50 份 RTL 和一份诊断、结构与运算组的 8 份 RTL、两份大图的 4 份 RTL 全部逐字节相同。

硬件资源、组合与时序求值、聚合循环和数值循环共通过 142 项现有测试。资源检查包含分配失败注入。循环回归同时覆盖源码和库两种入口。

最终宿主沿用调用方的临时分配器并传播错误后，重新运行硬件资源与逻辑求值，5 项全部通过。Yosys 分别对两个组合电路做了 72 次输入及故障检查，对时序电路核对了 14 个周期与 56 条信号记录。

## 时间与内存

使用 Zig 0.17.0 和 ReleaseSmall。对照工具使用提交 `6b9af646b` 的硬件实现；其后一次提交只迁移了求解流程。候选由上阶段 Source 工具重新引导，使用本阶段的 Source 分析和生成实现。两者使用同一组已分析的程序，交错运行七对取中位数。墙钟覆盖硬件图生成和两种 RTL 输出，CPU 与峰值 RSS 覆盖整个测量进程。每轮均验证摘要及分配释放平衡。
