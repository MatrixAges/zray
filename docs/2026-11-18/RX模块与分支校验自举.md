# RX 模块与分支校验自举

## Intent · 阶段目标

贯通编译、磁盘项目和 lint 的模块校验。迁移同层 Call 的输入要求、Type 和 Store 的重名定位、模块声明顺序，以及 If 和 Switch 的分支定位。校验要保留首个诊断的位置、优先级和原有的数据访问成本。父提交中，RX Schema、标签、语法适配、依赖图及底层 DSL 共有 41 个 Zig 文件、2,771 行；本阶段按退出正式路径的职责计量。

## Data · 入口与数据流

编译器建立 XML 依赖索引时已经遍历全部 Call。它现在同时检查显式输入、紧邻的 Call、带 out 的 Task 以及并行边界。在逆序遍历中保留源码位置最早的缺参节点。模块解码在原有的子标签、属性和 Module.fn 检查之后读取这个结果。lint 借用原始 XML 节点表，在当前 Module 的子树上执行同一个缺参谓词。

```mermaid
flowchart LR
    A[XML 语法节点] --> B[编译或磁盘项目的依赖索引]
    A --> C[lint XML 视图]
    B --> D[检查当前 Call 的输入来源]
    C --> D
    D --> E[首个缺参位置]
    E --> F[Module 校验]
    F --> G[Type 重名]
    G --> H[声明位置与 Store 重名]
```

模块声明的适配器一次收集 Type、Args 和 Store，只保存标签、借用的名字及实际子节点序号。普通步骤造成的序号间隙足以判断声明是否出现在步骤之后。Source 返回实际子节点序号，宿主可以直接定位错误。Switch 的文本 Case 和表达式 Case 各用一份固定容量的哈希表；表项指向实际分支位置。If 的 Else 和 Switch 的 Default 都由 Source 检查。

```mermaid
flowchart LR
    A[已解码的模块子节点] --> B[稀疏声明列]
    B --> C[ZX 查重与位置检查]
    D[已解码的分支] --> E[分支类别与借用的 Case 值]
    E --> F[RX 调度 Case 查重及后备分支检查]
    C --> G[原始子节点序号]
    F --> G
    G --> H[报告对应属性或标签的位置]
```

## Edges · 保留的边界

索引与不可变语法根的存储身份匹配后才能复用。直接传入手工 AST 且未提供解析索引的 API，以及初始 seed，仍使用 Zig 树遍历检查缺参。XML/DSL 解码、借用列的物理适配及诊断输出也仍有手写 Zig。声明及分支校验只处理当前模块，编译库权限、类型推导和所有权仍在各自的阶段执行。

## Answer · 验收

- Source 构建通过 25 步。候选重新生成 771 个入口，排除输入身份戳后，13,010 个文件逐字节相同。
- 使用显式与省略输入的普通调用、命名调用及 Task.out 分别生成相同的 Zig，首步缺参和并行兄弟隐式传参均被拒绝。
- 编译器 RX 单元回归通过 39 项，初始 seed 成功生成解析器。下游通过 513 项 Zig 测试、9 项磁盘项目 CLI 检查、55 项属性执行和 6 项属性拒绝检查。
- 两版 CLI 对 1,448 个 RX 文件只读运行 lint，逐文件退出码及完整诊断一致。另用五组宽输入检验重复声明和缺参的错误优先级，覆盖 2,048 个声明、分支或连续调用。三轮中位墙钟和 CPU 均持平，单进程峰值增加 0.05～0.23 MB，最大增量出现在 2,048 个 Type 名称的场景。
- 40 个实际入口的 3,343 个生成文件逐字节一致。冷生成三轮墙钟中位数 1.04 → 1.03 秒，CPU 5.32 → 5.31 秒，单进程峰值 468.7 → 467.9 MB。
