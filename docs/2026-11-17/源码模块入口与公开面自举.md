# 源码模块入口与公开面自举

## Intent

接续源码函数尾部迁移，把源码联结后的入口选择、公共成员发布和 Store 初始化器剩余遍历移入 RX/ZX。从源码项目和 RX 函数导入沿正式调用路径核对发布顺序、编号和借用范围。

## Data

`link/source.zig` 先复用递归函数或追加独立入口，再发布声明、初始化器和公共成员，最后读取公开端口。公共成员与初始化器已经复用单行 ZX 映射，但仍由 Zig 遍历和写入。初始化器的共享前缀必须保持引用，带命名空间的原始成员经过发布后不保留命名空间。

## Edges

保留递归入口判断使用的描述符身份、匿名入口冲突规则、原生内建成员标记、Store 初始值顺序与前缀选择。直接写入现有结构布局，Zig 负责生命周期和容量，以及递归候选的原始描述符比较。

## Answer

```mermaid
flowchart LR
    Tail[已发布函数尾部] --> Entry[选择递归入口或独立入口]
    Entry --> Decl[发布类型和常量]
    Decl --> Init[借用共享初始值前缀并写入其余行]
    Init --> Members[发布公共成员与匿名入口]
    Members --> Ports[解析最终公开端口]
```

```mermaid
flowchart LR
    Source[借用的源记录] --> Mapping[ZX 校验和编号映射]
    Mapping --> Target[原地写入预留记录]
    Shared[共享初始值记录] --> Prefix[保留共享前缀]
    Prefix --> Target
```

以既有源码、库链接、原生接口与 Store 回归，加同输入产物与相邻、固定性能基线验收。

## 实现

- ZX 计算尾行递归候选，保留描述符身份比较，选择复用已有函数、追加独立入口或发布纯类型模块。沿用原有函数范围映射。
- 公共成员按传入顺序批量写入预留记录，保留内建操作和可空端口，拒绝重复匿名入口。只有匿名入口时保持零成员分配。
- Store 初始值沿用已迁入 ZX 的共享前缀判定。命中完整前缀时直接借用，部分命中时用连续写入发布原先的共享记录，再由 ZX 批量映射和写入剩余记录。
- 新增的定距整数读取和可空列写入拆分到内部 `memory/columns` 声明，继续静态链接同一内存实现。声明拆分保持原 `memory` 接口和文件行数约束。
- Zig 仍协调 Source 的外层发布流程，负责容量与 ABI 排布，读取最终端口，比较递归候选的原始描述符，以及触发独立函数体物化。

## 验收

- 行为改动通过 143 个构建步骤、126 项 Zig 测试及 11 项 CLI 检查。内存声明拆分后，重新构建两代 Source 引导器，并复跑依赖该边界的源码链接、Store 初始化器和 RX 磁盘项目，82 个构建步骤、44 项 Zig 测试及 9 项 CLI 检查通过。
- 定向生成验证递归候选、纯类型入口、重复匿名入口拒绝、内建成员标记、可空端口映射和共享初始化器地址。
- 相邻工具使用同一份 739 入口清单，11,846 个生成文件与 5,387 条生成缓存记录一致。所有权缓存摘要同为 `23e7d2994a00b2a241a8c0518838392350f3b13d404169cedec7fd4de0fe5fca`。固定输入既有 134 份 Zig 文件差异的两侧摘要与上一阶段一致。
