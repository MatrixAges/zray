# 编译产物准入自举

## Intent

把编译产物联结中的布局、公开类型名称和常量准入迁入正式 RX。让产物联结、产物提取、缓存解码及 Program 校验直接借用已有常量记录。

## Data

旧的联结入口由 Zig 解释 RX 生成的步骤数组。布局检查之后预留函数和原生模块编号，再校验类型名称与常量。常量校验需要读取名称、类型和有效标量载荷，旧实现构造名称数组、指针数组、展开的字面量数组及临时表。

## Edges

保留布局错误早于编号预留、名称错误早于常量错误、导出早于导入的原有顺序。字符串与布尔常量校验只检查记录类型。整数的符号与范围、浮点可表示性、枚举成员索引继续使用共享校验规则。借用视图仅在本次调用期间有效。首次引导仍使用 seed；链接图遍历、原生联结、签名绑定、依赖校验与函数体写入仍有单独的宿主边界。

## Answer

```mermaid
flowchart LR
    Link[产物联结] --> Layout[RX 检查布局]
    Layout --> Mappings[宿主预留映射]
    Mappings --> Names[RX 检查公开名称]
    Names --> Values[RX 检查常量导出与导入]
    Values --> Binding[原生模块及函数联结]
```

```mermaid
flowchart LR
    Inputs[产物及 Program 现有记录] --> Columns[借用名称、类型和标量]
    Columns --> Name[ZX 检查名称与编号]
    Columns --> Value[ZX 按标签读取有效载荷]
    Value --> Rule[复用标量类型规则]
    Name --> Result[准入结果]
    Rule --> Result
```

验收覆盖真实联结、缓存恢复、类型边界、分配失败、分阶段自编译和同输入性能。

## 实现

- 联结入口直接进入模块准入 RX。布局通过才请求映射容量。宿主分配并初始化编号槽，再交回 RX 检查名称和常量。旧模块步骤数组与独立布局、名称宿主已退出正式路径。
- 产物准入、产物提取、语义缓存解码和 Program 校验复用同一种借用列。校验按标签读取有效载荷，复用已展开字面量的标量规则。编译库 Program 与 Store 初始值验证使用同一 Program 借用入口。
- 只读列直接指向现有 IR 记录。名称、字面量、字面量指针和外层表的临时分配已从这些路径移除。参与分析和绑定比较的已展开字面量保留现有输入形态。

## 验收

- 两代 Source 引导构建各通过 22 步，二进制 SHA-256 同为 `a89756530693b92fcd98ae19fd27508421dc67af6e9363c06782eeff57519f29`。
- 库联结、编解码、独立进程导入、模块产物、语义缓存和磁盘 RX 项目共通过 200 项 Zig 测试。缩减步骤枚举后去掉不可达的 Zig 默认分支，仅补跑受影响的联结边界和独立重联结，两项合计 22 项测试通过。磁盘 RX 和独立进程导入另有 15 项 CLI 检查通过。
- 零容量定向核验覆盖布局失败、映射先后、六种载荷、重复名称、非法编号、整数上下界、f32 精度、非有限浮点及枚举越界。
- 上一阶段与候选使用同一份 732 入口清单，11,866 份生成文件逐字节一致，5,394 条源码缓存键和负载摘要一致。所有权缓存摘要同为 `e8cc81e2e6b6ff112639489afa4b2fed3cabe876d95b0cd302ce90dedbcb3d7b`。固定输入仍有 134 份既有 Zig 差异，文件及双方内容哈希与上一阶段一致；文件清单另有一份差异。每个工具的同输入冷暖产物一致。
