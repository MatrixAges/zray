# 输入观测与快照复用自举

## Intent

让常驻构建的输入登记、重读、历史复用和失败写回由同一组 Source 流程决定。
避免给路径拼写与物理路径相同的输入再分配一份字符存储。

## Data

批首为 `55d0c6b87`。`watch/observation/registration.zig` 分别控制登记、
读取、消费记录及写回。`scan.zig` 在重读时同时比较、登记版本和重置临时区。
观测及快照目前分别复制逻辑、物理路径。正式发布及 watch 都依赖这些入口。

## Edges

保留已消费文件的摘要比较、目录观测升级、版本复用短路和原始错误。
读失败时继续写回失败事实，保持原有一致性条件。工作区与完整目录各自的
摘要算法保留。时钟、文件描述符、平台路径及哈希状态在原生边界操作。

```mermaid
flowchart LR
    Register["输入登记或消费记录"] --> Classify["Source 判定登记方式"]
    Classify --> Observe["读取或复用历史观测"]
    Observe --> Write["提交成功或失败事实"]
    Watch["快照轮询"] --> Compare["复用版本或重读比较"]
    Compare --> Accept["通过后登记版本"]
```

```mermaid
flowchart LR
    Slot["观测表中的已拥有逻辑路径"] --> Physical["解析物理路径"]
    Physical --> Shared["同路径共享字符存储"]
    Physical --> Distinct["不同路径拥有独立字符存储"]
    Shared --> Snapshot["快照接管有效副本"]
    Distinct --> Snapshot
```

## Answer

普通发布和 watch 共用观测槽位查询。登记和消费记录在 RX 中选择复用、
读取、比较和写回；ZX 按当前槽位状态判定是否升级目录观测。删除专用的
原生绑定文件和分散的写回入口。扫描只有在重读成功、结果未变且启用版本
检查时才更新版本。系统调用、摘要计算、哈希表与 arena 操作保留在原生边界。

观测直接借用映射表已拥有的路径。同名逻辑和物理路径在快照中共用一份字节，
不同路径独立存储。升级比较使用在比较结束时释放的临时 arena。

正式 ReleaseSmall 验证曾在首次消费记录时崩溃。优化后的 LLVM IR 对
ZX 原生引用参数标记 `readonly`，而宿主把该实参直接转回可写状态，后续
读取的路径被优化为未定义值。现在 Source 借用只读句柄，宿主通过句柄取得
独立的可写上下文。两者位于调用栈，生成的登记和消费流程无需堆分配。

最小复现已覆盖首次及重复消费记录、文件登记、目录升级、快照捕获和版本重读。
两套 Source 引导器和正式构建对同一观测清单生成的 43 个文件逐字节一致。
使用 Zig 0.17.0 和已经自编译的 Source 引导器构建正式 ReleaseSmall CLI。
正式 CLI 执行 Source 的观测流程。后端发布、后端运行、watch 恢复、库 watch、
C 头文件 watch 和 RX watch 六个回归目标全部通过。

### 性能与产物

固定对照沿用上一批安装版。固定对照、批首 `55d0c6b87` 和候选均使用
相同 Zig。三种禁用缓存的库发布各交错测量七次，墙钟中位数均为 0.01 秒，
63 个发布文件逐字节一致。候选的进程峰值 RSS 较批首分别变化
−64、+16、−32 KiB，三组均低于固定对照。

两个状态各有 20 个发布文件在三版之间逐字节一致。以下为中位数。
