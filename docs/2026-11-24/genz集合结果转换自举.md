# genz 集合结果转换自举

## Intent

将集合结果的成员转换、布局选择和发布接入 Source，撤出 Zig 上逐成员准备和集合专用布局流程。普通构造与集合结果共用布局准备和 AST 发布。

## Data

起点为 `c54b3aba1`。正式集合工作流先完成操作，再判断是否转换未采用状态表示的结果。现有 Zig 为每个元组成员准备转换资源，Source 随后发射转换。结果构造另外借用 AST，按指定布局或普通构造策略发布。

```mermaid
flowchart LR
    Operation["列表操作"] --> Convert["RX 结果转换"]
    Convert --> Prepare["ZX 成员扫描与资源准备"]
    Prepare --> Emit["RX 转换片段生成"]
    Emit --> Layout["共享 RX 构造与布局"]
    Layout --> Publish["宿主 AST 写入"]
```

```mermaid
flowchart LR
    Tuple["借用元组成员和表示事实"] --> Rows["填充同一组转换行"]
    Rows --> Bases["刷新 AST 基址"]
    Bases --> Converted["发射并发布转换结果"]
    Converted --> Construction["取得布局后借用 AST"]
    Construction --> Result["发布最终结果"]
```

## Edges

先按原元组顺序准备全部成员，再刷新表达式与字段编号基址。保持显式布局分支、状态来源处理和删除部分的提前返回。物理暂存区、AST 写入和类型物化通过现有宿主边界执行。

## Answer

沿集合正常路径和普通构造入口完成行为、产物与固定清单的冷暖生成对照。记录正式路径上退出的 Zig 职责以及保留的物理存储操作。

- RX 根据状态表示决定是否转换集合结果。ZX 借用元组类型与表示查询列，逐成员填写原有转换行。宿主只分配、填充转换行和刷新 AST 编号。转换暂存区沿用原来的作用域，在最终布局生成前释放。
- 普通与集合构造共享 Source 的布局选择与发射入口。显式目标略过类型物化。引用表示直接复用已取得的状态布局。旧 Zig 成员循环、集合终结器和两个独立生成入口退出。
- 构造仍借用布局物化后的 AST，沿用表达式、语句、引用和序列状态的写入顺序。原生层保留当前表示的布局查询及物理发布。
- 使用 `c54b3aba1` 的 Source 引导器构建 ReleaseSmall 候选，主清单使用 16 个分区。372 项编译器测试通过。同样五份清单除输入戳外，17,915 个生成文件逐字节一致。
- 使用同一批首引导器生成当前源码的编译器与应用，九组回归共 666 个构建步骤、14,314 项测试全部通过。覆盖集合原值、逆序、删除后 pop、严格区间、对象构造、reduce 批量追加及其所有权语义。

固定基线、批首和候选均由 Source 引导，运行 Source 分析与生成。冻结清单使用 Zig 0.17.0、16 个分区，关闭常驻生成。下表为三次交错运行的冷生成中位数。

较批首，冷生成墙钟减少 0.03 秒，CPU 减少 0.07 秒。进程树采样峰值减少 1.10 MB，单进程峰值增加 1.07 MB。较固定基线，冷墙钟减少 0.16 秒，CPU 增加 0.37 秒，进程树峰值减少 217.94 MB。
