# genz 迭代转换资源准备自举

## Intent

让迭代输入、返回、借用与类型布局的正式入口在 RX 完成策略判定、计划和资源解析。移除相同职责的 Zig 分派与多次生成入口交接。

## Data

起点为 `9a9558537`。四类路径分别由 Zig 调用策略和计划，再用同一资源解析算法填充布局和操作数。正常发射必须从已物化类型后的 AST 读取基址和视图。

```mermaid
flowchart LR
    In["输入、返回、借用与类型布局"] --> Plan["RX 策略与计划"]
    Plan --> Fill["共用 ZX 资源解析"]
    Fill --> Emit["AST 视图刷新与发射"]
    Emit --> Publish["迭代片段发布"]
```

```mermaid
flowchart LR
    Base["借用源类型表和缓存"] --> Decide["选择原值或资源计划"]
    Decide --> Reserve["预留布局及操作数"]
    Reserve --> Resolve["逐行物化类型"]
    Resolve --> Result["交付同一列缓冲"]
```

## Edges

输入、返回和借用保持原步骤先取得根布局，再判定原值分支。类型布局先命中已有缓存。沿用现有暂存区、布局和操作数的分配次序及物化算法。AST 发射入口在准备返回后读取最新基址。

## Answer

用固定 Source 引导器验证四类迭代路径与复合值。对比完整引导清单和固定输入的生成行为、性能及峰值内存。

- 四个 Source 入口按原顺序判定原值或原生类型，再建立计划并填充资源列。移除八个独立生成入口及 Zig 策略、计划和资源分派。借用和类型布局只分配布局列，输入和返回保持先布局、后操作数的分配次序。
- Source 逐行执行原有物化规则，宿主保留暂存区和物化调用。布局及操作数切片填入原来的发射形状，计划跨生成组按兼容布局借用，后续发射刷新 AST 基址和返回类型视图。
- 使用 `9a9558537` 的 Source 引导器构建 ReleaseSmall 候选，主清单使用 16 个分区。372 项编译器测试通过。五份清单除输入戳外，17,897 个文件逐字节一致。
- 同一批首引导器生成当前源码的应用。八组回归共 437 个构建步骤、635 项测试通过，覆盖迭代调用与缓冲、复合及模块循环、循环列、产品转移和借用视图。

固定基线、批首和候选均由 Source 引导，运行 Source 分析与生成。冻结清单使用 Zig 0.17.0、16 个分区，关闭常驻生成。下表为三次交错运行的冷生成中位数。

| 引导器                             |   墙钟 |    CPU | 采样进程树峰值 RSS | 单进程峰值 RSS |
| ---------------------------------- | -----: | -----: | -----------------: | -------------: |
| 固定基线 `declaration-preparation` | 2.06 s | 9.00 s |          738.87 MB |      767.28 MB |
| 批首 `9a9558537`                   | 1.95 s | 9.42 s |          520.39 MB |      534.17 MB |
| 候选                               | 1.89 s | 9.38 s |          524.35 MB |      545.24 MB |

较批首，冷生成墙钟减少 0.06 秒，CPU 减少 0.04 秒。采样进程树峰值增加 3.96 MB，单进程峰值增加 11.08 MB（2.1%），采样物理占用峰值增加 3.88 MB。候选单进程峰值样本为 544.57 至 551.85 MB，批首为 533.63 至 541.52 MB。较固定基线，冷墙钟减少 0.17 秒，CPU 增加 0.38 秒（4.2%），进程树峰值减少 214.52 MB。

热生成墙钟增加 0.01 秒，CPU 减少 0.01 秒。无修改生成墙钟保持 0.03 秒。冻结清单冷暖和批首对照的 9,894 个文件逐字节一致。
