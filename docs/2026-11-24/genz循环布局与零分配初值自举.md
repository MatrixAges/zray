# genz 循环布局与零分配初值自举

## Intent

让 Loop 的布局检查直接产出初值计划。修复带捕获谓词先分配引用对象再转入本地 Loop 状态的路径，保持源值求值顺序、结果 ABI 和借用约定。

## Data

起点为 `0739ede9c`。源码和库消费的带捕获谓词生成两次堆分配，分别用于捕获元组和 Loop 初值对象。现场跟踪显示，深层布局已选定，初值检查执行后，旧 Zig 布局入口仍从帧读到未设置的结果，后续初值计划选择了引用求值和深层转换。

```mermaid
    Facts["只读类型与 Loop 事实"] --> Probe["RX 推进布局检查"]
    Probe --> Answer["ZX 保存检查结果"]
```


## Edges

各项检查仍按原来的准入顺序按需运行。引用、值、丢弃和结果消费共用执行流程。前递表达式编号、可直接构造的结论和初值计划随生成调用的结果返回。宿主继续借用 IR，调用现有分析原语，并持有生成语句与资源的寿命。

## Answer

正式 Loop 调用链通过 `layout/execute.rx` 接续布局判断、检查结果推进与初值计划。移除 Zig 中逐轮写入布局帧和回读结果的逻辑、重复的原生动作枚举，以及布局选择和初值计划各自独立的两个生成入口。

以 `0739ede9c` 的 Source 引导器构建候选，编译器 372 项测试全部通过。使用同一 Source 引导器生成应用回归所用编译器，正式 Source 分析与生成通过 442 个构建步骤、569 项测试。24 组 Every 与 Some 零分配检查覆盖源码和库消费，并在拒绝堆分配时通过。检查正式应用编译器的 `every/scalar` 产物，捕获元组和初值对象从两次 `allocator.create` 降为本地布局构造，输入数组继续借用。

用批首与候选 Source 引导器运行当前五份清单，共 17,750 个输出逐字节一致。两者均执行 Source 分析与生成。这组引导清单和上述谓词夹具分别验证自举输出稳定性和预期的应用生成变化。
