# 编译库导入缓存与初值自举

## Intent

迁移源码与 RX 项目共用的编译库导入。让 Source 决定首次装载的容量、导出
索引与可见长度，并在原表尾直接写入 Store 初值。已装载库复用已有导出索引。

## Data

批首为 `ef315ffc0`。普通模块 `Project` 与 RX 混合正文分别将正式导入请求
交给 `compiled.imports.load`。现有 RX 负责缓存顺序，Zig 的预留回调负责初值
容量及索引分配，安装版把初值写入独立数组，发布回调再复制到项目初值表。
缓存命中后由 Zig 包装二次 Source 调用以定位公开名称。

## Edges

新增缓存优先于继承快照。首次装载前仍按同一顺序预留缓存、初值和导出索引。
扩容时旧初值前缀继续服务已发布的签名与历史视图。初值尾部只在库安装成功后
进入可见范围。缺少公开成员的诊断发生在装载成功和登记之后，沿用原有顺序。
宿主继续绑定物理哈希表、路径解析和表视图。

```mermaid

    Import["源码或 RX 导入"] --> Lookup["查找新增及继承缓存"]
    Lookup -->|"首次导入"| Reserve["预留缓存、初值尾部与名称索引"]
    Reserve --> Link["安装库并写入预留尾部"]
    Link --> Commit["交付初值长度与缓存"]
    Lookup -->|"命中"| Select["查找公开成员"]

```

    Table --> Write
    Write --> Publish["更新可见长度"]

## Answer

两个正式调用方共用 Source 预留和成员定位。缓存未命中时，ZX 在初始化器
表预留容量和名称索引。RX 只在联结成功后推进可见长度，再将单元与索引交给缓存。
使用旧容量或扩容后的新尾部直接接收重定位结果，省去原先单独分配再追加的初值表。
扩容继续留存已借出的前缀。命中的公开名字通过同一个 ZX 查找函数解析。

旧 Zig 预留与追加只由初始 seed 路径使用。正式生成的公开成员查找回调及其
独立生成入口已删除。缓存哈希槽、存储描述符借用、路径拼接和联结器调用仍由
宿主提供。检查生成的导入子图，缓存命中没有临时堆分配。
