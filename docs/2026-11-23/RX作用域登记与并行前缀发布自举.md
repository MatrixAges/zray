# RX 作用域登记与并行前缀发布自举

## Intent

从 `ad1816794` 接续。普通绑定与并行结果共用 Source 的碰撞扫描、待验证的冲突行提交、失败前缀保留和结果发布，移除作用域登记的 Zig 循环。

## Data

正式路径已通过 ZX 判断路径重叠及值状态。Zig 执行扫描轮次，先更新待验证冲突表的长度，再把已通过的并行绑定发布到可见作用域。扩容、继续扫描和报告冲突都在两项提交之后。[扫描规则](../../packages/compiler/src/rx/analysis/inference/scope/register.zx) · [原驱动](../../packages/compiler/src/rx/analysis/inference/scope/collisions.zig)

```mermaid
flowchart LR
    Ordinary["普通绑定与已有作用域"] --> Scan["扫描潜在冲突"]
    Parallel["并行结果之间"] --> Scan
    Scan --> Deferred["提交待验证冲突对"]
    Deferred --> Prefix["发布通过的并行前缀"]
    Prefix --> Action["继续、扩容或报告冲突"]
```

## Edges

保留路径重叠、Void 跳过、待验证结果和报告跨度。并行多个结果只比较当前行与之前的结果。冲突对或输出分配失败时保留原本已提交的前缀。名称、节点 ID 和跨度继续按列批量写入，随后提交可见长度。保留 seed。

```mermaid
flowchart LR
    Source["借用并行输出列"] --> Reserve["保留目标空间"]
    Reserve --> Copy["按列复制刚通过的行"]
    Copy --> Length["提交作用域长度"]
    Length --> Visible["下一阶段可见"]
```

## Answer

普通与并行入口共用 RX 循环。每轮由 ZX 推进扫描并写入待验证冲突对，RX 提交冲突表长度，发布通过的并行前缀，再决定扩容、继续或报错。零结果直接返回，单结果沿同一列发布入口提交。

作用域只预留本次通过的行。ZX 依次批量写名称视图、节点 ID 和跨度，最后才增加目标的可见长度。按行扫描和物理分配保持原来的调用次序，名称的底层字节继续借用。Zig 只绑定列、处理实际容量和交付带源跨度的诊断。旧 Zig 循环和作用域整段追加入口从正式路径移除。

原登记算法在主引导清单中生成。注册入口现在需要执行阶段的原生分配和诊断接口，已移入执行清单，并将作用域源码登记为该生成步骤的输入。初次完整构建在主清单缺少宿主声明处停止。调整清单后候选通过 27 个引导步骤。

### 行为与引导验证

- 登记和绑定传播两条入口定向生成通过，RX/ZX 格式及 lint 通过。生成的批量列写入不分配中间缓冲。
- 上一阶段工具和候选对同一份当前源码运行主编译器、执行、宿主、集合和增长清单，17,696 个生成文件逐字节一致。10 个常驻编辑和错误恢复场景的结果与上一阶段一致。
- 正式路径通过 153 项 Zig 回归和 17 项 CLI 集成。现有回归覆盖并行兄弟路径重叠、独立结果、冲突位置和分配失败。
- 初始 seed 通过 50 个步骤和 39 项 RX 测试。候选 Source 引导器 SHA-256 为 `fcc1dbefe18ba949bc52497e9cb83f09af90090f3e8fcffc189ab0f2026536a1`。
