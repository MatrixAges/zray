# 硬件 SMT 项读取与缓存自举

## Intent

让硬件图构造直接调用 Source 项读取。把读取位置、递归深度、操作数和节点驻留决策从 Zig 迁出。

## Data

现有 RX 已识别令牌头，ZX 已核对结束边界和操作数类型。`e01180216` 的 `terms/reader.zig` 还负责更新位置、递归读取、查询变量、解析算子、探测缓存及提交节点。[令牌头](../../packages/compiler/src/backends/hardware/terms/read.rx)

```mermaid
flowchart LR
    Text[表达式的借用字节] --> Head[读取项头]
    Head --> Operand[按原顺序读取操作数]
    Head --> Binding[读取原有变量]
    Operand --> Close[消费右括号并检查类型]
    Close --> Cache[按原文本查询节点缓存]
    Binding --> Cache
    Cache --> Publish[复用已有节点或登记新节点]
    Publish --> End[核对表达式结束]
```

## Edges

保留从左到右的求值顺序、变量对布尔词的覆盖、原样文本缓存键、扩容和失败顺序以及定义来源。节点和槽的实际存储、原生字节视图及静态算子查表暂由 Zig 提供。初始 seed 保有独立解析路径。

## Answer

复用硬件资源、HDL 仿真、验证和契约回归，检查生成函数的分配与复制，比较实际 Verilog、JSON 和性能。用同一份引导清单核对候选再生成结果。

### 实现

定义、输出和安全节点共用 RX 项入口。RX 依次准备输入、读取一项和核对末尾，ZX 复用既有令牌头解析、边界检查和类型规则。读取位置由 Source 推进，借用同一个图构造帧里的标量槽。递归按原来的顺序访问操作数，保留原深度和长度上限。[入口](../../packages/compiler/src/backends/hardware/terms/parse/run.rx) · [递归读取](../../packages/compiler/src/backends/hardware/terms/parse/walk.zx)

节点缓存直接借用原索引的键和值。Source 使用现有字节表探测，先处理命中，需要增长时再借用新表槽。节点上限和位宽由 Source 校验，分配成功后提交节点与槽。缓存键仍指向原 SMT 字节，新增节点沿用当前定义来源。正式入口退出旧 `terms/reader.zig` 和 `Index.entry` 调度。[缓存登记](../../packages/compiler/src/backends/hardware/terms/parse/intern.zx) · [物理存储](../../packages/compiler/src/backends/hardware/construction/workflow.zig)

节点布局、索引的物理扩容和再散列、原生算子静态查表及项位置槽仍由 Zig 承接。局部引导产物未新增堆分配或字节复制。

### 验收

候选引导器由 `e01180216` 的 Source 引导工具构建，25 步通过。重新生成主清单、所有权增长、集合及执行四组文件，15,906 份文件与构建产物逐字节一致，排除工具身份戳。

硬件资源、HDL 仿真、验证资源、验证和契约通过 91 个构建步骤及 14 项 Zig 测试。Yosys 组合逻辑通过两组各 72 条检查，时序逻辑通过 14 周期、56 条记录。原有分配失败回归验证了错误返回和节点资源清理。

### 性能

macOS arm64、Zig 0.17.0、ReleaseSmall。两套 CLI 由 Source 引导器生成，并使用 Source 分析与发射。对照为 `e01180216`，沿用六组 FPGA 负载和求解器，关闭缓存和常驻生成，预热后交错取七轮中位数。每组 Verilog 和 JSON 均逐字节一致。
