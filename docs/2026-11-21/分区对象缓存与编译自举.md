# 分区对象缓存与编译自举

## Intent

让独立分区对象编译器由 Source 推进共享缓存键、分区摘要、对象可用性、失效、编译和结果发布。沿用单独构建的 `partition-objects` 可执行文件。

## Data

解析请求、选择清单成员、判断重用和序列化状态已由 Source 执行。其余遍历与调度仍由对象编译入口负责，同一缓存状态跨越运行前失效和运行后发布。[对象编译入口](../../packages/compiler/build/partition/compile.zig)

```mermaid
flowchart LR
    R[请求和清单] --> H[共享输入与分区摘要]
    H --> P[观察对象并规划]
    P --> N{需要编译}
    N -->|是| I[按需撤销旧记录]
    I --> C[编译待处理分区]
    C --> F[收集并按顺序报告]
    F --> S[原子发布成功记录]
    N -->|否| X[返回]
```

## Edges

保持分区摘要字段、散列编码和参数次序。计划中的失效写入失败时不启动子进程。失败的分区仍允许其他任务完成，只有成功项可以发布。诊断写入失败时沿用现有错误和状态。目录、文件读取、密码散列状态和子进程仍由原有 Zig 标准库接口提供。

## Answer

RX 串联共享输入、分区摘要、对象观察、编译和发布，计划全命中时直接返回。ZX 遍历输入、分区摘要区间、对象路径和有序诊断。失效写入先于实际编译，成功记录在报告诊断后原子发布。编排借用摘要偏移、路径和编译结果，通过空容量分配器执行。Zig 仍负责临时哈希缓冲、目录和文件读取、原子替换及等待子进程，目录内的文件枚举和散列 I/O 仍在宿主方法内。[编排](../../packages/genz/src/analysis/partition/cache/workflow/run.rx) · [宿主](../../packages/compiler/build/partition/driver.zig)

由 `652af3ccc` 的 Source 引导器构建，25 个步骤通过。仓库初始 seed 也能生成 Host 清单并链接对象工具，所得工具命中相同的 16 个分区，产物及时间戳保持一致。前后两代正式 `zxc-bootstrap` 逐字节相同，因此沿用上一批的固定清单和常驻编辑性能证据。本批重新计时独立对象编译器。

四分区夹具覆盖首次构建、完整缓存命中、只改一个分区、失效记录写入失败、编译失败后重试、删除对象、外部目录内容变化和关闭诊断输出。两代工具对照一致，包括有序诊断、失败后成功记录、四份对象和状态文件。关闭诊断输出时两代都停止发布，并能恢复。

macOS arm64、Zig 0.17.0、ReleaseSmall，用上一阶段对象工具作同输入对照。两代工具在同一份正式 16 分区生成树上各做一次冷对象构建及五次热查验。每次冷构建前清空同一基准路径的 Zig 本地缓存与该工具的输出目录，复用 Zig 工具链全局缓存，记录父进程及实际 Zig 子进程。
