# 硬件图校验与整模块输出自举

## Intent

把正式硬件图校验和 Verilog 整模块输出接到 RX/ZX。校验遍历、输出顺序与短路决策都由 Source 执行。

## Data

现有 ZX 能校验一个节点、生成页眉、写一个节点和完成文件。批量校验、预留与整图输出的调用顺序仍由原生入口推进。[图视图](../../packages/compiler/src/backends/hardware/graph/view.zig) · [Verilog 入口](../../packages/compiler/src/backends/verilog/root.zig)

```mermaid
flowchart LR
    Graph[借用硬件图] --> Nodes[校验节点及统计输入]
    Nodes --> Ports[核对安全节点和端口表]
    Ports --> Reserve[预留 Verilog 缓冲]
    Reserve --> Header[写页眉与端口]
    Header --> Wires[顺序写节点]
    Wires --> Finish[输出连线及可选时序外壳]
    Finish --> Result[交付字节缓冲]
```

## Edges

保持校验在分配输出前完成，遇到首个非法节点即停止。两个遍历借用同一份节点，按需读取字段。宿主持有分配器和通用 writer，保留原有分配失败、写入失败及缓冲清理行为。

## Answer

验收非法图拒绝、分配失败清理、组合与时序仿真。用上一提交的正式 CLI 对照 Verilog、JSON、墙钟、CPU 和峰值 RSS，核对 Source 引导产物及节点循环的分配形态。

### 实现

独立硬件图校验与 Verilog 入口共用 RX 校验。ZX 按节点顺序检查并统计输入，失败时停止，RX 继续检查安全节点和端口。校验通过后，Verilog RX 计算尺寸并预留输出，按顺序写页眉、节点和尾部。[校验编排](../../packages/compiler/src/backends/hardware/graph/validate.rx) · [Verilog 编排](../../packages/compiler/src/backends/verilog/workflow/render.rx)

最初的节点接口返回完整记录，生成器因此为校验循环分配临时状态。最终接口借用节点地址，验证和写入按需读取字段。两个入口的生成函数无临时堆分配或字节复制指令。Zig 视图保留原始节点、端口和类型列的借用，以及原生 union 字段的投影。Verilog 宿主管理分配器、字节 writer、失败清理和输出移交。

### 验收

候选引导器由 `f547375a4` 的 Source 引导工具构建，25 步通过。用它重新生成主清单、所有权增长、集合和执行四组文件，15,906 份文件与构建时逐字节一致，排除工具身份戳。

硬件资源、HDL 仿真、验证资源、验证和契约通过 91 个构建步骤及 14 项 Zig 测试。18 种非法图分别经独立校验、组合及带时钟输出，一律拒绝。Yosys 组合逻辑通过两组各 72 条检查，时序逻辑通过 14 周期、56 条信号记录。分配失败清理沿用原资源回归。

### 性能

macOS arm64、Zig 0.17.0、ReleaseSmall。两套 CLI 由 Source 引导器生成，使用 Source 分析及发射。沿用 `f547375a4` 的六组 FPGA 负载和求解器，关闭缓存和常驻生成，交错运行，预热后取七轮中位数。各组 Verilog 和 JSON 逐字节一致。
