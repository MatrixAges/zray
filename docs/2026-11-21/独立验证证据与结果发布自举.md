# 独立验证证据与结果发布自举

## Intent

把独立验证的证明准备、求解结果分派、反例绑定和诊断输出合入正式 RX 调用链。

## Data

`verification.check` 供独立验证、FPGA、公开库和编译前验收共用。现有 RX 已负责求解流程及证据文件写入，Zig 仍计算摘要、选择默认路径、处理求解结果并逐行输出反例绑定。[正式入口](../../packages/compiler/src/verification/solver.zig) · [求解编排](../../packages/compiler/src/verification/solver/check.rx)

```mermaid
flowchart LR
    Query[生成的查询或诊断] --> Decide[分派准备或报告诊断]
    Decide --> Evidence[序列化证据并选择路径]
    Evidence --> Solver[现有求解与证据编排]
    Solver --> Outcome[按求解结果发布]
    Outcome --> Bindings[按原序输出反例绑定]
    Outcome --> API[交付结果或既有错误]
```

## Edges

保留证据 JSON、默认目录摘要、证据文件、退出码、错误映射和报告字节。证据 JSON 借用原生 IR 交由 Zig 标准库序列化。摘要与路径使用固定栈缓冲，只有默认路径需要摘要；分块哈希保持原字节顺序，避免合并查询缓冲。绑定按列借用，不构造副本。

## Answer

复用验证、契约及硬件回归，核对默认和指定路径、成功、反例及求解失败的实际文件和诊断。对照受影响的 CLI 性能和同输入引导结果。

### 实现

RX 根据是否得到可验证的查询决定准备证据或输出诊断，调用既有求解流程，再按结果选择输出方式。ZX 借用原有输入名称和路径列，在反例中按原顺序输出绑定。Zig 只在公开边界把求解结果映射到原有返回值和错误。[发布编排](../../packages/compiler/src/verification/solver/publication/run.rx) · [反例绑定](../../packages/compiler/src/verification/solver/publication/counterexample.zx) · [公开边界](../../packages/compiler/src/verification/solver.zig)

默认路径使用三个原始字节视图依序更新 SHA-256，在固定缓冲区复用现有十六进制输出。指定路径时省去摘要。JSON 仍用 Zig 标准库按原字段顺序序列化原生 IR。生成代码中的 I/O 调用保留固定大小的参数描述符，证据和查询字节按引用传递，未为反例输入创建副本。[默认路径](../../packages/compiler/src/verification/solver/publication/path.zx)

求解入口迁入执行清单后，文件和进程模块开始从同一执行清单绑定其函数签名。其他标准接口沿用主清单的签名，标准库实现仍在同一份模块中。[构建类型绑定](../../packages/compiler/build/standard_types.zig)

### 验收

候选由 `e84764763` 的 Source 引导工具构建，25 步通过。重新生成主清单、所有权增长、集合和执行清单，15,907 份文件与构建时逐字节一致，排除工具身份戳。

硬件资源、HDL 仿真、验证资源、验证和契约通过 91 个构建步骤及 14 项 Zig 测试。组合逻辑通过两组各 72 条检查，时序逻辑覆盖 14 周期、56 条记录。12 组验证对照覆盖默认与指定路径、反例、版本失败、执行失败、无效应答、不可满足和未知结果。83 份证据文件、标准诊断和退出码一致。6 组 FPGA 对照的 Verilog 和 JSON 一致。

对三个默认路径分别从实际证据 JSON、可满足性和正确性文件独立复算 SHA-256，摘要与证明目录名一致。

### 性能

macOS arm64、Zig 0.17.0、ReleaseSmall。两套 CLI 由 Source 引导器生成，运行 Source 分析与发射。对照提交为 `e84764763`，关闭缓存和常驻生成，预热后对六组验证和六组 FPGA 负载各取七轮交错中位数。失败分支另外核对证据和行为。受影响用例的墙钟、CPU 增量至多为 0.45 毫秒和 0.21 毫秒，峰值 RSS 最多增加 32 KiB。
